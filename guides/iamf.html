.iamf Immersive Audio Model & Formats
Format Overview v1.1.0 Specification
OBU_IA_Sequence_Header
OBU Type 31
Structural Wrapper
The global master packet that identifies the file as IAMF and sets the primary decoding rules.
Example: ia_code: "iamf"
Identifies the IAMF payload and declares the architectural profiles in use.
ia_code
4 Bytes
Primitive Variable
A fixed signature used for bitstream synchronization.
Example: "iamf" (0x69616d66)
The mandatory ASCII string required to identify the start of a valid IAMF sequence.
primary_profile
Value
Primitive Variable
A numeric selection defining the complexity tier of the stream.
Example: 2
Sets the computational and feature constraints of the bitstream.
Accepted Parameters:
0=Simple Profile(Limited to static channel beds up to 7.1)
1=Base Profile(Enables 1st-order Ambisonics and 7.1.4 objects)
2=Base-Enhanced Profile(Enables 3rd-order Ambisonics and massive 24ch arrays)
OBU_IA_Codec_Config
OBU Type 0
Structural Wrapper
Initializes the audio decoder for specific formats like Opus or AAC.
Example: codec_id: "Opus"
Defines the specific codec parameters and initialization requirements.
codec_id
4 Bytes
Primitive Variable
A 4-character code (FourCC) naming the codec.
Example: "Opus"
Specifies the compression algorithm utilized in the audio element substreams.
Accepted FourCC Strings:
Opus=Opus Codec(Streaming optimized)
mp4a=AAC-LC(Broad compatibility)
fLaC=FLAC(Lossless compression)
ipcm=Linear PCM(Uncompressed raw audio)
audio_roll_distance
Int
Primitive Variable
Sets the seek-point pre-roll in samples.
Example: 3840
Ensures the decoder can prime its internal state for seamless playback starting at any frame.
Requirements:
> 0:Lossy Codecs(Required for Opus and AAC)
0:Lossless/Raw(Must be zero for FLAC or PCM)
OBU_IA_Audio_Element
OBU Type 1
Structural Wrapper
Defines how audio substreams are combined to form a spatial scene or object.
Example: audio_element_type: 1
The foundational OBU for defining the physical and spatial makeup of the audio content.
audio_element_type
Value
Primitive Variable
Defines the fundamental spatial paradigm of the substreams.
Example: 2
Categorizes the audio as either fixed speakers, a soundfield, or discrete objects.
Accepted Parameters:
0=Channel-Based(Standard surround beds like 5.1/7.1.4)
1=Scene-Based(Ambisonics HOA Soundfields)
2=Object-Based(Discrete items with XYZ trajectories)
ScalableChannelLayoutConfig
Struct
Complex Data Payload
A configuration block determining how many channels are decoded based on playback hardware.
Example: { num_layers: 2 }
Enables "one-to-many" delivery by defining layers for mono, stereo, and surround.
num_layers
Value
Primitive Variable
The number of scalable channel configurations provided.
Example: 3
Defines the count of distinct hierarchies (e.g., Layer 1 = Stereo, Layer 2 = 5.1, Layer 3 = 7.1.4).
Accepted Parameters:
1-7:Numeric Count(Maximum of 7 scalable tiers per element)
loudspeaker_layout
Value
Primitive Variable
The standard channel configuration for the current layer.
Example: 10
Identifies the speaker arrangement for the current layer.
Accepted Parameters:
0=Mono(Center only)
1=Stereo(L/R)
2=5.1.0 Surround(Standard cinematic)
10=7.1.4 Immersive(Includes 4 height channels)
15=Expanded(Triggers expanded_loudspeaker_layout)
expanded_loudspeaker_layout
8-Bit
Primitive Variable
A deeper field used only when loudspeaker_layout is set to 15.
Example: 13
Unlocks massive hardware-specific channel arrays for Eclipsa Audio environments.
Accepted Parameters:
8=9.1.6 ch(16 Channels - Base-Enhanced Profile)
13=10.2.9.3 ch(24 Channels - Advanced Eclipsa)
19=Top-5 ch(Full overhead height ring)
AmbisonicsConfig
Struct
Complex Data Payload
Defines scene-based encoding for the soundfield.
Example: { ambisonics_mode: 1 }
Configures scene-based rendering using spherical harmonic expansion.
ambisonics_mode
Value
Primitive Variable
Selects the Ambisonic processing method.
Example: 0
Dictates how the substreams map to spherical harmonics.
Accepted Parameters:
0=AMBISONICS_MONO(Strict channel mapping)
1=AMBISONICS_PROJECTION(Linear projection matrix)
ambisonics_order
Value
Primitive Variable
Defines the mathematical order of the HOA soundfield.
Example: 3
Sets the spatial resolution. Higher orders provide more precise directional imaging.
Accepted Parameters:
1-3:HOA Order(Order 3 supports up to 16 channels)
OBU_IA_Mix_Presentation
OBU Type 2
Structural Wrapper
The "Mix Instruction" packet; dictates how beds and objects are combined for the user.
Example: num_sub_mixes: 1
Carries the final mix instructions, loudness targets, and headphone rendering rules.
Loudness Info (ITU-R BS.1770-4)
Struct
Complex Data Payload
A bundle of mandatory loudness normalization values.
Example: { integrated_loudness: -2400 }
Critical compliance data ensuring consistent playback volume across content sources.
integrated_loudness
16-Bit Int
Primitive Variable
Target loudness in LKFS (expressed in Q8.8 format).
Example: -2400 (=-24.0 LKFS)
The measured integrated loudness over the entire duration of the presentation.
anchor_element
Value
Primitive Variable
Defines the perceptual anchor for normalization.
Example: 1
Sets which audio element the loudness measurements were prioritized against.
Accepted Parameters:
1=Dialogue Anchor(Leveling based on speech clarity)
2=Album Anchor(Leveling based on musical energy)
rendering_config
Struct
Complex Data Payload
Sets rules for converting spatial content to various hardware endpoints.
Example: { headphones_rendering_mode: 1 }
Instructs the renderer on how to handle headphones and downmixing.
headphones_rendering_mode
Value
Primitive Variable
Toggles 3D spatialization for headphones.
Example: 1
Determines if headphone listeners receive a basic stereo downmix or full HRTF-based binaural audio.
Accepted Parameters:
0=Stereo Mode(Simple 2.0 downmix)
1=Binaural Mode(3D spatial rendering via HRTF)
OBU_IA_Parameter_Block
OBU Type 3
Structural Wrapper
Carries time-varying metadata (trajectory/gain) for specific frames.
Example: subblock_duration: 1024
Provides the real-time instructions for object movement and gain modulation.
SinglePositionParameterData
Struct
Complex Data Payload
The Cartesian coordinates and animation logic for an audio object.
Example: { azimuth: 4500 }
Defines the 3D location of an object in a spherical coordinate system.
animation_type
Value
Primitive Variable
Instructions on how to calculate position over time.
Example: 1
Directs the renderer to interpolate between coordinate updates.
Accepted Parameters:
0=Step(Instant jump to new coordinates)
1=Linear(Straight-line movement between points)
2=Bezier(Smooth curve trajectory interpolation)
coordinates (azimuth, elevation, distance)
Float
Primitive Variable
The raw Cartesian/Spherical data for object tracking.
Example: "azimuth": 45.0
Defines where the object sits in 3D space relative to the listener.
Accepted Ranges:
Azimuth:-180.0° to 180.0°(Left to Right horizontal axis)
Elevation:-90.0° to 90.0°(Down to Up vertical axis)
Distance:0.0 to 1.0(Scalar depth/closeness)
