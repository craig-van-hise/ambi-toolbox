.iamf Immersive Audio Model & Formats
Format Overview v1.1 Specification
OBU_IA_Sequence_Header
OBU Type 31
Structural Wrapper
Open Bitstream Unit: A packetized container that encapsulates data. Type 31 acts as the global master descriptor.
Example: Header payload declaring 'Base-Enhanced' profile active.
The global configuration for the entire IAMF stream, defining profiles and versioning.
primary_profile
Value
Primitive Variable
Value: A numeric selection defining the complexity tier of the stream.
Example: 2 (Base-Enhanced Profile)
Dictates the complexity tier of the stream, restricting or unlocking features like massive channel layouts.
Accepted Parameters:
0 = Simple Profile (Channel-based only, limited to 5.1/7.1 layouts)
1 = Base Profile (Adds 1st-order Ambisonics, Binaural, and 7.1.4)
2 = Base-Enhanced Profile (Unlocks 3rd-order Ambisonics and massive 24ch arrays)
OBU_IA_Codec_Config
OBU Type 0
Structural Wrapper
Open Bitstream Unit: A packet containing initialization data required to set up the audio decoder.
Example: Payload containing specific Opus channel counts and magic signatures.
Defines the specific codec initialization data. Essential for setting up the audio decoder.
codec_id
4 Bytes
Primitive Variable
4 Bytes: A 32-bit integer typically represented as a 4-character ASCII string (FourCC).
Example: 0x4F707573 (Hex for "Opus")
A Four-Character Code (FourCC) strictly identifying the encapsulated audio format. User inputs the ASCII text string.
Accepted FourCC Strings (ASCII):
Opus=Opus Interactive Audio Codec
mp4a=Advanced Audio Coding (AAC-LC)
fLaC=Free Lossless Audio Codec
ipcm=Linear PCM (Uncompressed)
audio_roll_distance
Value
Primitive Variable
Value: A positive integer instructing the decoder how many samples to pre-roll before rendering audio.
Example: 3840 (Common pre-roll for Opus)
Critical for random access; specifies how many samples prior to the target timestamp must be decoded to prime the decoder's internal state.
Constraints:
Int > 0=Positive Integer(Required for lossy codecs like Opus/AAC to establish state)
0=Zero Value(MUST be 0 if codec is fLaC or ipcm)
OBU_IA_Audio_Element
OBU Type 1
Structural Wrapper
Open Bitstream Unit: A packet describing the layout of an audio object, channel bed, or Ambisonics scene.
Example: Payload defining a discrete 7.1.4 channel bed structure.
Describes the structure of an audio object, channel bed, or Ambisonics scene, defining how substreams are combined.
audio_element_type
Value
Primitive Variable
Value: A numeric selection defining the structural paradigm of the audio payload.
Example: 1 (Scene Based)
Fundamentally changes how the decoder interprets the subsequent data routing.
Accepted Parameters:
0=CHANNEL_BASED(Traditional speaker target layouts)
1=SCENE_BASED(Ambisonics soundfield via spherical harmonics)
2=OBJECT_BASED(Discrete dynamic items with Cartesian coordinates)
3-7=Reserved(For future specification expansion)
ScalableChannelLayoutConfig
Struct
Complex Data Payload
Struct (Structure): A grouping of multiple variables (like layer depth and channel config) bundled together.
Example: { num_layers: 2, loudspeaker_layout: 9 }
Allows a decoder to download or decode only the channels it needs. Triggered by Type 0.
loudspeaker_layout & num_layers
Value
Primitive Variable
Value: Standard mapping parameters for the stream geometry.
Example: 2 (5.1 surround)
Defines standard channel arrays and scalability.
Accepted Parameters:
Layers:1 to 7(Defines the hierarchy depth)
0=Mono(Single channel center)
1=Stereo(Left / Right pair)
2=5.1 Surround(Standard cinema layout)
15=Expanded Layout(Triggers parsing of expanded_loudspeaker_layout)
expanded_loudspeaker_layout
8-Bit
Primitive Variable
8-Bit Integer: A small data size used to select highly specific, massive speaker layouts.
Example: 8 (Representing 9.1.6ch)
Parsed when standard layout is set to 15. Supports ultra-immersive, high-density hardware setups.
Accepted Parameters:
8=9.1.6ch(16 Channel Immersive)
13=10.2.9.3ch(24 Channel Immersive - Eclipsa)
18=Top-1ch(TpC "Voice of God" overhead)
19=Top-5ch(Full overhead ring array)
OBU_IA_Mix_Presentation
OBU Type 2
Structural Wrapper
Open Bitstream Unit: A packet containing the rendering and mixing rules for the final output.
Example: Payload defining the volume routing for an English 5.1 mix.
Contains the rendering and mixing rules (loudness, gain, layout targeting) for the final output.
Loudness Info (ITU-R BS.1770-4)
Struct
Complex Data Payload
Struct: Bundles several loudness metrics together, ensuring the audio meets strict broadcast regulations.
Example: { integrated_loudness: -24 LKFS, true_peak: -1.5 dBTP }
Mandatory loudness compliance data. Carries integrated_loudness and maximum true_peak (dBTP).
anchor_element
Value
Primitive Variable
Value: Selection defining perceptual leveling targets.
Example: 1 (Dialogue Anchor)
Allows content normalization based on a specific perceptual element rather than the whole mix.
Accepted Parameters:
0=Unknown Anchor(Generic leveling)
1=Dialogue Anchor(Leveling based on speech)
2=Album Anchor(Leveling based on overall music program)
rendering_config
Struct
Complex Data Payload
Struct: Instructs the renderer on algorithmic application.
Example: { headphones_rendering_mode: 1 }
Determines the specific mathematical playback engine utilized.
headphones_rendering_mode
Value
Primitive Variable
Value: Toggles spatial 3D audio for headsets.
Example: 1
Directs how standard layouts should be converted when the endpoint is a pair of headphones.
Accepted Parameters:
0=STEREO(Basic 2.0 channel downmix)
1=BINAURAL(HRTF-based 3D spatialization)
OBU_IA_Parameter_Block
OBU Type 3
Structural Wrapper
Open Bitstream Unit: A packet carrying time-varying dynamic metadata for a specific frame duration.
Example: Payload updating an object's X, Y, Z coordinates for frame 1024.
Carries time-varying dynamic metadata (demixing coefficients, spatial positions) for a specific duration.
DemixingInfoParameterData
Struct
Complex Data Payload
Struct: Bundles mathematical keys to unfold a downmix.
Example: { dmixp_mode: 0 }
Provides the key to unfold a downmix back into a high-channel-count mix.
dmixp_mode
3-Bit
Primitive Variable
3-Bit Integer: Selects one of 8 preset demixing parametric combinations.
Example: 0
Defines the values of alpha, beta, gamma, and delta used in the demixing matrix.
Accepted Parameters (0-7):
0=Mode 1(Standard cinematic demixing coefficients)
1=Mode 2(Flatter energy distribution weighting)
2=Mode 3(Front-focused spatial weighting)
3-7=Reserved(Future matrix configurations)
SinglePositionParameterData
Struct
Complex Data Payload
Struct: Bundles precise 3D mathematical coordinates.
Example: { animation_type: 1, azimuth: 45.0 }
Carries the 3D coordinates moving objects through space. Includes azimuth, elevation, and distance.
animation_type & coordinates
Value
Primitive Variable
Value: Instructions on how to calculate position vectors over time.
Example: 2 (Bezier curve interpolation)
Defines how the renderer should interpolate positions between updates, and the Cartesian limits.
Accepted Parameters:
0=Step(Immediate coordinate jump)
1=Linear(Direct line interpolation)
2=Bezier(Smooth curve interpolation)
Azimuth:-180.0° to 180.0°(Horizontal axis range)
Elev.:-90.0° to 90.0°(Vertical axis range)
