# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
Following the 3-column UI migration, the application suffers from a "cold boot" playback issue. When files are initially dropped into the application, nothing is selected. Furthermore, hitting the master "Play" button does nothing because the `TransportContext` requires a stream to be explicitly initialized (currently only happening via double-click). The objective is to auto-select the first ingested file and enable a "Smart Play" handoff that seamlessly initializes the audio stream on the first play click.

## 2. Technical Decisions & Dependencies
* **Queue Auto-Hydration:** A `useEffect` in the queue state management will monitor array length and automatically assign the first index if the active pointer is null.
* **Smart Play Interception:** The Transport UI component will bridge `useFileQueue` and `useTransport`. If the user presses play while `currentFile` is null, it will intercept the command and execute `setCurrentFile(activeFile.path, true)`.

## 3. Implementation Phases

### Phase 1: Queue Auto-Selection (`useFileQueue.ts`) — ✅ Completed
* **Objective:** Ensure the first file dragged into an empty app is automatically selected as the `activeFile`.
* **Instructions:**
    1. Open `src/hooks/useFileQueue.ts` (or the corresponding context file managing this state).
    2. Add a `useEffect` that monitors the `files` array and the `activeFile` state.
    3. **Implementation Logic:**
       ```typescript
       useEffect(() => {
           // If we have files in the queue, but no active file is selected, select the first one.
           if (files.length > 0 && !activeFile) {
               setActiveFile(files[0]);
           }
       }, [files, activeFile, setActiveFile]);
       ```
* **TDD Checkpoint:**
    * **Test Case 1:** **Given** an empty queue, **When** a new array of files is set, **Then** assert that `activeFile` immediately equals `files[0]`.
    * **AGENT INSTRUCTION:** "Set Phase status to 🔵 Active. Implement the auto-selection logic. Once the tests pass or the logic is cleanly integrated, set status to ✅ Completed."

### Phase 2: Smart Play Handoff (`Transport.tsx`) — ✅ Completed
* **Objective:** Allow the Transport's Play button to initiate a stream from the `activeFile` if the engine is cold.
* **Instructions:**
    1. Open `src/components/Transport.tsx`.
    2. Ensure both hooks are imported: 
       `import { useTransport } from '../contexts/TransportContext';`
       `import { useFileQueue } from '../hooks/useFileQueue';`
    3. Destructure `activeFile` from the queue hook, and `currentFile`, `setCurrentFile`, and `togglePlayPause` from the transport hook.
    4. Locate the `onClick` handler assigned to the master Play/Pause button.
    5. **Implementation Logic:**
       ```typescript
       const handlePlayClick = () => {
           // If the transport has no initialized stream, but we have a selected file in the UI...
           if (!currentFile && activeFile) {
               // Cold-boot the stream and force playback
               setCurrentFile(activeFile.path, true);
           } else {
               // Otherwise, behave normally
               togglePlayPause();
           }
       };
       ```
    6. Bind `handlePlayClick` to the Play button's `onClick` event.
* **TDD Checkpoint:**
    * **AGENT INSTRUCTION:** "Set Phase status to 🔵 Active. Implement the Smart Play interception logic in the Transport component. Set status to ✅ Completed."
    * **HUMAN VALIDATION REQUIRED:** "STOP. Ask the user to refresh the app, drag a file into the empty queue, verify it highlights immediately, and click the Transport Play button. Confirm that the audio stream initializes and begins playback without requiring a double-click."
