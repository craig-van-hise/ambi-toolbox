# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
status: ✅ Completed
**Project:** AmbiToolbox
**Current State:** The backend streaming server is using FFmpeg's default stereo downmix (`-ac 2`) for the `render=stereo` preview path. This causes raw Ambisonic spherical harmonics to be routed as discrete cinematic channels, destroying the spatial image.
**Objective:** Implement a deterministic 1st-Order Ambisonic to Stereo Cardioid decoding matrix using the FFmpeg `pan` filter for all `render=stereo` stream requests.

## 2. Technical Decisions & Dependencies
status: ✅ Completed
* **Root Cause:** FFmpeg does not natively understand ACN/SN3D Ambisonics without a specific decoding matrix. It routes Ch 0 (W) to Left and Ch 1 (Y) to Right, ignoring the mathematical relationship of the spatial format.
* **Architecture Fix:** We will intercept the `render=stereo` parameter in the streaming backend (likely `electron/main.ts` or `electron/handlers/ObrHandler.ts`) and inject a specific audio filter graph (`-af`).
* **The Matrix Math:** We will decode the first-order channels (0, 1, 3) into a virtual XY cardioid pair. 
  * Left = 0.5*W + 0.354*X + 0.354*Y
  * Right = 0.5*W + 0.354*X - 0.354*Y
  * **FFmpeg Syntax:** `pan=stereo|c0=0.5*c0+0.354*c3+0.354*c1|c1=0.5*c0+0.354*c3-0.354*c1`

### Phase 1: FFmpeg Argument Injection
status: ✅ Completed
* **Objective:** Replace the default `-ac 2` downmix with the precise AmbiX `pan` filter.
* **Instructions:**
    1. Open the backend streaming logic responsible for generating the FFmpeg command when `http://127.0.0.1:45455/obr-stream` is called (likely `electron/handlers/ObrHandler.ts` or `electron/main.ts`).

    5. Ensure this argument is *only* applied when `render === 'stereo'`. Do not apply this to the binaural/OBR rendering path.

### Phase 2: High-Order Truncation Safety
status: ✅ Completed
* **Objective:** Ensure files with more than 4 channels (e.g., 2nd/3rd/4th order) do not crash the `pan` filter.
* **Instructions:**
    1. FFmpeg's `pan` filter will safely ignore unused higher-order channels (c4, c5, etc.) when outputting to `stereo` based on the mapping string provided in Phase 1. 
    2. However, verify that no upstream `-ac` arguments are artificially truncating the input *before* the filter is applied. The input must read all channels, pass them to the filter graph, and the filter graph handles the reduction to 2 channels.
* **TDD Checkpoint:** AGENT INSTRUCTION: Verify the backend streaming logs. Ensure FFmpeg is not throwing "channel mapping errors" when processing 9-channel or 16-channel files through the new `pan` filter.
