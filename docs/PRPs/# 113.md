# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
status: ✅ Completed
**Project:** AmbiToolbox
**Current State:** Playback suffers from a consistent "startup hiccup" ~1 second after a track begins or a seek occurs. This is caused by the backend pipeline's warm-up latency; it trickles the first few frames to the frontend, causing the browser to begin playback prematurely and immediately starve.
**Objective:** Eliminate the startup starvation by implementing a `PrimeBuffer` (a custom Node.js Transform stream). This buffer will intercept the Opus encoder output and block transmission to the HTTP response until a minimum threshold of audio data (a "burst") has been accumulated.

## 2. Technical Decisions & Dependencies
status: ✅ Completed
* **Root Cause:** The browser's media demuxer aggressively starts playback the moment it receives the Ogg headers and the first audio frame, outpacing the backend pipeline's initial CPU warm-up speed.
* **Architecture Fix:** We will create a custom `Transform` stream that buffers the raw stream chunks in memory. 
* **Math & Thresholds:** The stream is encoded at 256 kbps (32 Kilobytes per second). We will set a `primeThreshold` of 48 KB (49,152 bytes). This forces the backend to successfully encode ~1.5 seconds of audio before sending a single byte to the frontend, guaranteeing a deep initial buffer.

## 3. Implementation Phases
status: ✅ Completed

### Phase 1: Construct the PrimeBuffer Class
status: ✅ Completed
* **Objective:** Create the custom Transform stream logic in the backend handler.
* **Instructions:**
    1. Open the file managing the streaming endpoint (likely `electron/handlers/ObrHandler.ts` or `electron/main.ts`).
    2. Ensure `Transform` is imported from the native `stream` module: `import { Transform } from 'stream';`
    3. Add the following class definition above your streaming endpoint logic:

    ```typescript
    class PrimeBuffer extends Transform {
        private chunks: Buffer[] = [];
        private totalSize = 0;
        private primed = false;
        private primeThreshold = 48 * 1024; // 48KB (~1.5s of 256kbps Opus)

        _transform(chunk: Buffer, encoding: BufferEncoding, callback: Function) {
            if (this.primed) {
                this.push(chunk);
            } else {
                this.chunks.push(chunk);
                this.totalSize += chunk.length;
                if (this.totalSize >= this.primeThreshold) {
                    this.primed = true;
                    this.push(Buffer.concat(this.chunks));
                    this.chunks = []; // Free memory
                }
            }
            callback();
        }

        _flush(callback: Function) {
            if (!this.primed && this.chunks.length > 0) {
                this.push(Buffer.concat(this.chunks));
            }
            callback();
        }
    }
    ```

### Phase 2: Inject the PrimeBuffer into the Pipeline
status: ✅ Completed
* **Objective:** Route the final encoder output through the `PrimeBuffer` before it reaches the HTTP response.
* **Instructions:**
    1. In the same file, locate the stream teardown/setup block where the final `Encoder` process is piped to the HTTP `res` object (e.g., `encoder.stdout.pipe(res)`).
    2. Instantiate the new buffer per request: 
       `const primeBuffer = new PrimeBuffer();`
    3. Modify the pipeline to route through it:
       `encoder.stdout.pipe(primeBuffer).pipe(res);`
    4. Ensure that in your stream teardown logic (when a seek occurs or the user stops playback), `primeBuffer.destroy()` is called alongside the child process `kill()` commands to prevent memory leaks.
