# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
status: ✅ Completed
**Project:** AmbiToolbox
**Current State:** During continuous playback of high-order spatial audio, the user experiences occasional silent dropouts. The frontend UI does not indicate buffering during these events because the `isRebuilding` state is only triggered by explicit user actions.
**Objective:** Eliminate playback micro-stutters by optimizing the backend IPC pipeline buffers, and wire the HTML5 `<audio>` element's native starvation events to the UI's `BUFFERING` indicator.

## 2. Technical Decisions & Dependencies
status: ✅ Completed
* **Root Cause 1 (Frontend Visibility):** The `waiting` and `stalled` events on the `HTMLAudioElement` are unhandled.
* **Root Cause 2 (Backend Starvation):** The 3-stage `Decoder -> OBR -> Encoder` pipeline suffers from Node.js default stream backpressure. Passing raw PCM between spawned processes requires larger `highWaterMark` buffers and FFmpeg queue optimizations.
* **Architecture Fix:** 1. Bind `waiting` to set `isRebuilding = true` and `playing` to set `isRebuilding = false`.
    2. In the backend streaming handler (likely `ObrHandler.ts`), inject FFmpeg arguments `-max_muxing_queue_size 9999` and `-fflags +genpts` to the decoder/encoder stages, and ensure any Node `pipe()` calls use explicitly larger buffers if applicable.

## 3. Implementation Phases
status: ✅ Completed

### Phase 1: Frontend Buffer Instrumentation
status: ✅ Completed
* **Objective:** Ensure the UI accurately reflects when the HTML5 audio element is starved for data.
* **Instructions:**
    1. Open `src/contexts/PlaybackContext.tsx`.
    2. Locate the `useEffect` block where native audio event listeners are attached (e.g., `timeupdate`, `loadedmetadata`, `ended`).
    3. Add a new listener for the `waiting` event. When it fires, call `setState(prev => ({ ...prev, isRebuilding: true }))`.
    4. Ensure the existing `play` or `playing` event listener explicitly clears the lock: `setState(prev => ({ ...prev, isRebuilding: false }))`.
    5. Clean up these new listeners in the `return () => { ... }` teardown block.
* **TDD Checkpoint:** AGENT INSTRUCTION: Start the frontend server. You will not be able to reliably trigger a micro-stutter on command, but verify TypeScript compilation passes and no React dependency loop warnings are introduced.

### Phase 2: Backend IPC Pipeline Hardening
status: ✅ Completed
* **Objective:** Expand the inter-process buffers to prevent backpressure stutters.
* **Instructions:**
    1. Open the backend streaming logic (likely `electron/handlers/ObrHandler.ts` based on the 3-stage pipeline architecture).
    2. Locate the `spawn` arguments for the **Decoder** FFmpeg process. Add `['-max_muxing_queue_size', '9999']` to its output arguments before it pipes to OBR.
    3. Locate the `spawn` arguments for the **Encoder** FFmpeg process. Add `['-fflags', '+genpts', '-max_muxing_queue_size', '9999']` to its input/output arguments.
    4. If the Node.js `pipe()` method is used manually in the code (e.g., `decoder.stdout.pipe(obr.stdin)`), investigate if `highWaterMark` can be increased, or rely on the FFmpeg queue expansion above to handle the smoothing.
* **TDD Checkpoint:** AGENT INSTRUCTION: Launch the application and load a 3rd-order Ambisonic test file. Press play and let it run continuously for 60 seconds. Do not proceed to Phase 3 until you are confident the backend pipeline boots successfully with the new queue arguments without immediately crashing.
