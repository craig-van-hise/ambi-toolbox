#### **Phase 1: Project Scaffolding**

#### **Phase 2: Core Implementation (The Backend)**

Modify `electron/main.ts` to handle file conversion:

1. **IPC Handler:** Create an `ipcMain.handle` listener named `'convert-file'`.
2. **FFmpeg Logic:** Inside the handler, use `cross-spawn` to call `ffmpeg`.
3. **The Command:** You must use **exactly** these arguments to ensure 3rd Order Ambisonics compatibility (fixing the "16 channel vs Ambisonic" metadata issue):
* `-y` (Overwrite output)
* `-i` `[INPUT_FILE_PATH]`
* `-af` `aformat=channel_layouts=ambisonic` (**CRITICAL**: This forces the 16 channels to be treated as a scene-based soundfield).
* `-c:a` `libopus`
* `-b:a` `2560k` (High bitrate for 16 channels).
* `-f` `iamf`
* `[OUTPUT_FILE_PATH]` (Same filename as input, but with `.iamf` extension).


4. **Error Handling:** Wrap this in a Promise. Resolve on process exit code `0`, reject on non-zero or error events.

#### **Phase 3: The Bridge**

Update `electron/preload.ts`:

1. Expose a function `convertFile(path: string)` via `contextBridge`.
2. Ensure strict TypeScript typing for the exposed API.

#### **Phase 4: The UI (Frontend)**

Rewrite `src/App.tsx` to be a modern, dark-mode drag-and-drop interface:

1. **State Management:** Track `status` ('idle', 'processing', 'done', 'error') and `message` (string).
2. **Visuals:** Use Tailwind to create a large, dashed drop zone.
* *Idle:* Gray border, "Drag Ambisonics File Here".
* *Processing:* Yellow pulsing border, "Converting...".
* *Done:* Green border, "Success! File saved."

3. **Logic:** On the `drop` event, extract `files[0].path` (Note: Electron exposes the full system path on the File object, you may need `// @ts-ignore` or a custom interface extension to access it without TS errors). Send this path to the main process via the bridge.
