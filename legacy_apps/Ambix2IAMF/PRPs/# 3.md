

**Feature Update: Quality Selector UI & Bitrate Logic**

**1. Requirement Change:**
We are moving away from fixed bitrates. We need a **"Quality" dropdown** in the UI that determines the bitrate *per channel*.
This allows the bitrate to scale automatically regardless of the Ambisonics Order (1st, 2nd, or 3rd).

**2. The Options:**
Please add a Combobox/Select menu to `App.tsx` with the following options:

* **Low:** 32 kbps/channel
* **Medium:** 64 kbps/channel
* **High:** 96 kbps/channel *(Default)*
* **Highest:** 128 kbps/channel

**3. The Logic (Backend):**
Update the IPC handler and `iamf-config-generator.ts` to accept this quality setting.
Calculate the `target_bitrate` using this formula:
`target_bitrate = input_channel_count * selected_quality_kbps * 1000`

*Example:*

* Input: 3rd Order (16 channels)
* User Selects: "High" (96k)
* Calculation: `16 * 96 * 1000 = 1,536,000` bps.

**4. Implementation Tasks:**

* **Frontend (`App.tsx`):** Add the `<select>` element styled with Tailwind. Pass the selected value (integer: 32, 64, 96, or 128) to the backend.
* **Bridge (`preload.ts`):** Update `convertFile` signature to accept `(path: string, qualityPerCh: number)`.
* **Backend (`iamf-config-generator.ts`):** Use the formula above to set the `bitrate` field in the generated `.textproto` file before running the encoder.
