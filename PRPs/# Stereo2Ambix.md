
**A. Feature Context**
You are tasked with engineering and integrating the `Stereo2Ambix` feature into the existing AmbiToolbox codebase. AmbiToolbox is an Electron Modular Monolith utilizing a React/Tailwind frontend, a TypeScript IPC backend, and a Python data processing subsystem. This offline processing utility must upmix standard two-channel stereophonic audio into scalable Higher-Order Ambisonic (HOA) formats, strictly adhering to the AmbiX format (ACN channel ordering, SN3D normalization) up to 7th order.

You must engineer a high-density, completely fail-safe offline rendering pipeline. The underlying DSP architecture will synthesize a localized frontal virtual soundstage combined with a fully diffuse 3D envelopment field.

**C. Phased Implementation & TDD Strategy**
You will strictly adhere to Test-Driven Development (TDD) principles, breaking the build into the following sequential phases.

* **Phase 1: The "Walking Skeleton" & Interfaces**
* Define the TypeScript configuration payload `Stereo2AmbixOptions` in `src/types/index.ts`, consisting strictly of primitive types. Parameters must include target order, stage width, and envelopment intensity.


* Write failing unit tests (using Jest and Pytest) for parameter validation, matrix shape assertions (e.g., $(N+1)^2$ channels), and deterministic ingestion caching mechanics.




* **Phase 2: The Frontend Presentation Layer (React + Tailwind CSS)**
* Construct the `Stereo2AmbixView.tsx` component within the existing routing hierarchy.


* Integrate the global `FileQueue` dropzone for standardized file ingestion.


* Implement user controls strictly limited to high-impact variables: a dropdown for Target HOA Order (1st-7th), a slider for Stage Width, and a toggle/slider combination for 3D Envelopment.


* Wire the component to the global `SettingsContext` for persistent state and trigger the backend execution via `ipcRenderer.invoke`.




* **Phase 3: The Backend IPC Handler (TypeScript/Electron)**
* Create a dedicated modular handler at `electron/handlers/Stereo2Ambix.ts`.


* Implement deterministic ingestion caching: Generate a cryptographic MD5 hash of the incoming audio payload and requested parameters to instantly bypass redundant computational overhead if an identical output footprint exists.


* If no cache match exists, spawn the Python child process, piping the configuration payload as CLI arguments.


* Continuously parse the standard output (`stdout`) stream for JSON-formatted progress updates and emit those events back to the React UI to drive the determinist progress bar.




* **Phase 4: Python DSP - Data I/O and Primary-Ambience Extraction**
* Create `py/stereo_to_ambix.py`.


* To prevent Out-Of-Memory (OOM) crashes on massive 64-channel renderings, strictly implement a block-processing loop using `soundfile.blocks` (e.g., 4096 frames).


* Apply a Short-Time Fourier Transform (STFT) with a 50% overlap Hann window to each chunk.


* Implement an **Adaptive Weighted Principal Component Analysis (PCA)** algorithm. Utilize `numpy.linalg.eig` on the covariance matrix for every discrete time-frequency bin. Apply dynamic cross-correlation weighting to the principal eigenvectors to prevent eigenvalue inversion and safely isolate the correlated primary stream from the uncorrelated ambient stream.




* **Phase 5: Python DSP - Spatialization and Diffusion**
* 
*Virtual Soundstage (Primary):* Treat the extracted left and right primary signals as discrete virtual sources. Utilize **Constant Power Panning** laws to route the signals to the precise positive and negative azimuth angles defined by the user's Stage Width parameter without losing temporal energy. Multiply these signals by the spatial matrices generated by `spaudiopy.sph.sht` to encode them into the AmbiX format (ACN/SN3D).


* 
*3D Envelopment (Ambient):* Route the extracted ambient stream through a Feedback Delay Network (FDN). To guarantee mathematical stability and zero CPU floating-point multiplication overhead, utilize a **16x16 Hadamard matrix** for the unitary feedback loop. Map the resulting mutually uncorrelated outputs to the remaining ACN channels.


* Sum the encoded primary and diffused ambient matrices, perform an ISTFT, append the block to the output file, and `sys.stdout.flush()` the JSON progress strings.

*

Because the PCA outputs are mathematically orthogonal , you must assert that when these two un-spatialized, un-reverberated streams are summed and passed through an ISTFT, they mathematically null perfectly against the original source input, proving zero-phase destruction during the extraction phase.
