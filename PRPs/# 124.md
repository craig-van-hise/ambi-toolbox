# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
status: ✅ Completed
Playback for `.iamf` files is currently failing to start. Log analysis indicates that the `/probe-metadata` HTTP endpoint is invoking `probeAudio()` directly on the raw `.iamf` file. Because FFmpeg cannot parse IAMF, `ffprobe` fails, returning 0 channels. The React frontend (`PlaybackContext.tsx`) requires a channel count > 0 to proceed to Step 3 (Stream Commit), so playback permanently stalls at Step 2.

The objective is to fix this race condition by routing the file through the `IngestionRouter` *before* probing it. By doing this, `ffprobe` will scan the valid `.wav` proxy generated by the router, successfully returning the correct channel count and unblocking the frontend state machine.

## 2. Technical Decisions & Dependencies
status: ✅ Completed
* **Pre-Probe Transcoding:** The `/probe-metadata` endpoint in `main.ts` MUST await `IngestionRouter.prepareStreamTarget()` before executing `probeAudio()`. 
* **Caching Benefit:** Because `prepareStreamTarget` utilizes a hashed cache for temp files, calling it during the probe phase will pre-transcode the file. When the frontend subsequently requests `/obr-stream`, the router will instantly return the cached `.wav` proxy, ensuring zero added latency during track switching.
