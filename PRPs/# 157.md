
Please fix a race condition in the audio streaming pipeline that causes the backend to crash with `code null`. The issue occurs because `TransportContext` is calling `audio.play()` on the HTMLMediaElement before the backend streaming server has finished establishing its pipes, causing the browser to abort the connection.

We need to update the `Play/Pause Sync` hook in `src/contexts/TransportContext.tsx` to respect the `isRebuilding` state provided by `AudioEngineContext`.

**Target File:** `src/contexts/TransportContext.tsx`

1. First, ensure `isRebuilding` is extracted from `useAudioEngine()` at the top of the context provider (it already is).
2. Locate the `// Play/Pause Sync` `useEffect` block.
3. Add `isRebuilding` to the dependency array.
4. Add a guard so that `audio.play()` is **only** called if `isRebuilding` is `false`. 

Replace the current `Play/Pause Sync` block with this updated version:

```typescript
    // Play/Pause Sync
    useEffect(() => {
        const audio = audioRef.current;
        // Ensure we don't try to play an empty source
        if (!audio || !audio.src || audio.src === 'about:blank') return;

        // If we want to play, BUT the engine is rebuilding, do nothing. 
        // Wait for the canplay event to clear the isRebuilding lock.
        if (isPlaying && !isRebuilding && audio.paused) {
            audio.play().catch(e => {
                if (e.name !== 'AbortError') console.error('[Transport] Play failed:', e);
            });
        } else if (!isPlaying && !audio.paused) {
            audio.pause();
        }
    }, [isPlaying, isRebuilding, audioRef]);
```

**How this works:**
When a file is double-clicked, `commitStream` is called, which sets `isRebuilding` to `true`. Even though `isPlaying` immediately becomes `true`, this hook will safely do nothing. Once the backend establishes the stream and sends enough audio data, the `<audio>` element fires its native `canplay` event. `AudioEngineContext` catches this, drops `isRebuilding` to `false`, which triggers this hook again, finally executing `audio.play()` safely.
