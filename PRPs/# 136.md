# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
This execution phase addresses two specific regressions introduced during the previous layout and icon restorations. First, the `AmbiRotate` module exhibits structural instability: as the rotational values increase in digit count (e.g., from 0° to 180°), the physical width of the text node forces the parent flex card to expand. This triggers unwanted `flex-wrap` jumping. Second, the Transport's "Play" button is firing a broken payload, resulting in a backend crash (`[Pipeline] OBR exited with code null`). This was likely caused by the agent mangling the `onClick` handler while manually patching the legacy icons.

## 2. Technical Decisions & Dependencies
* **Dimensional Stability (AmbiRotate):** To prevent flex-wrap jumping, the outermost container of the `<Knob />` component in `src/tools/AmbiRotate/components/Knob.tsx` must be assigned a strict, rigid width (e.g., `w-32` or `w-[140px]`) and `shrink-0`. 
* **Dynamic Font Scaling:** To satisfy the user's request for the numbers to shrink as digits are added, implement a dynamic font-size calculation based on string length within the `Knob.tsx` text element.
* **Play Button State Restoration:** The crash log `[Transport] Play failed: null` indicates that the `Play` button in `src/components/Transport.tsx` is either passing `null` to the playback engine or failing to read the currently active file from the queue. The agent must inspect the contexts (`TransportContext.tsx` or `PlaybackContext.tsx`) to bind the correct `resume` or `play` method without overriding the active file payload.
