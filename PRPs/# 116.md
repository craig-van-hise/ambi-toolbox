
# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives

**Project:** AmbiToolbox
**Current State:** 7th-order Ambisonic (64ch) playback fails because FFmpeg rejects the `25c` channel layout string in the `pan` filter, causing a pipeline collapse.
**Objective:** Correct the backend truncation logic to successfully downscale high-order files to **4th-order (25 channels)** for the OBR renderer.

## 2. Technical Decisions & Dependencies

* **Root Cause:** FFmpeg's `pan` filter requires a recognized layout or a specific "discrete" syntax. Using `pan=25c` is invalid.
* **Architecture Fix:** We will use the `pan` filter with the **`unknown`** layout or explicitly define the 25 channels using the `0x1FFFFFF` bitmask (which represents 25 discrete channels) or, more simply, use the `-lavfi` syntax that FFmpeg understands for discrete mapping.
* **The Correct Filter:** `pan=manual|c0=c0|c1=c1|...|c24=c24` or using the `-filter_complex` channelmap tool. However, the most robust way in a piped `spawn` environment is:
`pan=25|c0=c0|c1=c1|...|c24=c24` (dropping the 'c' from the layout name).

## 3. Implementation Phases

### Phase 1: Corrected Backend 4th-Order Truncation

* **Objective:** Update `ObrHandler.ts` with the valid FFmpeg truncation syntax.
* **Instructions:**
1. Open `electron/handlers/ObrHandler.ts`.
2. Locate the logic in `createObrPipeline` that generates the `decoderArgs`.
3. If `channels > 25`, use this exact syntax for the `pan` filter:
* **Layout String:** `25` (just the number, no 'c').
* **Mapping:** `Array.from({length: 25}, (_, i) => "c" + i + "=c" + i).join('|')`.


4. The final filter argument should look like: `['-af', 'pan=25|c0=c0|c1=c1|...|c24=c24']`.
5. Update the `obr` process to strictly expect 25 channels: `'--channels', '25'`.
