# Product Requirements Prompt (PRP): Layout Unmapping & HRTF Gain

## 1. The Root Bug: Channel Shuffling

The spatial math is currently scrambling because FFmpeg is guessing the input layout is `hexadecagonal`. This causes FFmpeg to internally re-route the 16 raw AmbiX channels to surround-sound physical positions (e.g., Track 3 is sent to LFE) *before* the `pan` filter receives them. This destroys the ACN ordering.

## 2. Action 1: Force Raw Channel Ingestion

You must explicitly tell FFmpeg to treat the input as 16 unmapped, raw channels.

* **The Fix:** In your `child_process.spawn` arguments, replace the `-ac 16` flag with the strict layout flag: `-ch_layout 16c`
* **Placement:** This flag **MUST** be placed immediately before the `-i` flag in the arguments array. If it is placed after `-i`, it will apply to the output instead of the input, and the demuxer will still guess the layout.

## 3. Action 2: Compensate for HRTF Attenuation

Convolution naturally lowers the output volume because HRTFs simulate acoustic shadowing. The resulting WebM stream is currently too quiet.

* **The Fix:** Add a `gain` parameter to your `sofalizer` string to boost the output by 12dB.
* **Syntax Update:** `sofalizer=sofa='...':gain=12:speakers='FL 0 0|FR 180 0|...'`
