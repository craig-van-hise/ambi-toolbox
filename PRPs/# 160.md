# Product Requirements Prompt (PRP) — [Status Marker] 🔵 Active

## 1. Project Context & Objectives
**Context:** The `Ambix2Bin` tool allows users to downmix Ambisonics to binaural using SOFA (HRTF) files. The project bundles three standard files in `assets/hrtf/` and allows for custom file selection.
**Issue:** Selecting a built-in HRTF profile (e.g., Neumann KU100) results in the backend throwing: `Error: Custom SOFA file not found at: Neumann_KU100_48k.sofa`. 
**Root Cause:** A desync between the frontend dropdown value and the backend's path resolution logic. The backend fails to map the incoming string to a bundled asset path, falls back to treating it as a custom absolute path, and fails the existence check.
**Objective:** Standardize the HRTF selection payload using strict IDs, and implement robust absolute path resolution in the backend for bundled assets (handling both `dev` and `production` electron paths).

## 2. Technical Decisions & Dependencies
To definitively resolve this disconnect, the agent must implement the following architectural mandates:
1.  **Strict Payload Contract:** The frontend must send a specific payload structure to the backend, separating the profile ID from custom paths. E.g., `{ profileId: 'neumann' | 'kemar' | 'h3' | 'custom', customPath?: string }`.
2.  **Backend Path Resolution:** In `Ambix2Bin.ts`, the backend must explicitly map the `profileId` to the bundled `.sofa` filenames.
3.  **Electron Asset Pathing:** The backend must construct the absolute path to the bundled files dynamically using standard Electron environment checks (e.g., differentiating between `app.getAppPath()` for dev and `process.resourcesPath` for production builds).
