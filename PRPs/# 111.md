# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
status: ✅ Completed
**Project:** AmbiToolbox
**Current State:** The 3-stage audio streaming pipeline (`Decoder -> OBR -> Encoder`) suffers from severe micro-stutters and dropouts (approx. 5 times per 25 seconds). The M1 hardware is underutilized, indicating an IPC backpressure and stream fragmentation issue.
**Objective:** Eliminate IPC thrashing and frontend audio starvation by implementing "Deep Buffering" using Node.js `PassThrough` streams with massive `highWaterMark` allocations between the child processes and the HTTP response.

## 2. Technical Decisions & Dependencies
status: ✅ Completed
* **Root Cause:** Node.js default pipe buffers are 64KB. Passing 2.3MB/s of 16-channel PCM data causes the pipes to fill every 27ms, resulting in violent process pausing/resuming (thrashing) and fragmented HTTP chunking.
* **Architecture Fix:** We will use `stream.PassThrough` from the native Node.js `stream` module. We will instantiate custom buffers with a `highWaterMark` of 10MB.
* **Implementation Strategy:** Instead of doing `decoder.stdout.pipe(obr.stdin)`, we will do `decoder.stdout.pipe(deepBuffer).pipe(obr.stdin)`. We will apply this to the final HTTP response as well to ensure the browser receives large, contiguous chunks.

## 3. Implementation Phases
status: ✅ Completed

### Phase 1: Stream Import & HTTP Response Buffering
status: ✅ Completed
* **Objective:** Ensure the final encoded data is aggregated into large chunks before being sent over the HTTP network to the frontend `<audio>` element.
* **Instructions:**
    1. Open the file managing the streaming endpoint (likely `electron/handlers/ObrHandler.ts` or `electron/main.ts`).
    2. Import the `PassThrough` stream at the top of the file: `import { PassThrough } from 'stream';`
    3. Locate where the final Encoder's `stdout` is piped to the HTTP `res` object (e.g., `encoder.stdout.pipe(res)`).
    4. Create a deep buffer right before the pipe:
       `const httpBuffer = new PassThrough({ highWaterMark: 1024 * 1024 * 10 }); // 10MB`
    5. Route the final output through the buffer:
       `encoder.stdout.pipe(httpBuffer).pipe(res);`
* **TDD Checkpoint:** AGENT INSTRUCTION: Launch the application and load the 3rd-order test file. Play the file. Monitor if the buffering frequency decreases. Do not proceed to Phase 2 until the HTTP buffer is successfully integrated without throwing stream closure errors.

### Phase 2: IPC Pipeline Deep Buffering
status: ✅ Completed
* **Objective:** Eliminate the 64KB thrashing between the intermediate processes.
* **Instructions:**
    1. In the same handler, locate the connections between the `Decoder`, `OBR`, and `Encoder` processes.
    2. Instantiate intermediate buffers for the raw PCM handoffs:
       `const pcmBuffer1 = new PassThrough({ highWaterMark: 1024 * 1024 * 10 }); // 10MB`
       `const pcmBuffer2 = new PassThrough({ highWaterMark: 1024 * 1024 * 10 }); // 10MB`
    3. Reroute the pipes:
       Replace `decoder.stdout.pipe(obr.stdin)` with `decoder.stdout.pipe(pcmBuffer1).pipe(obr.stdin)`.
       Replace `obr.stdout.pipe(encoder.stdin)` with `obr.stdout.pipe(pcmBuffer2).pipe(encoder.stdin)`.
    4. Ensure proper error handling. If `decoder` emits an `error` or `close`, explicitly `.destroy()` the `pcmBuffer1` to prevent memory leaks. Do the same for all buffers in the teardown lifecycle.
* **TDD Checkpoint:** AGENT INSTRUCTION: Start the application. Load a heavy 3rd-order Ambisonic file. Play the file continuously for its entire 25+ second duration. Do not mark this phase as complete until the file plays from start to finish with **zero dropouts** and zero `BUFFERING` indicators flashing on the UI.

### Phase 3: Resource Cleanup Validation
status: ✅ Completed
* **Objective:** Ensure these massive 10MB buffers do not cause a memory leak when the user scrubs or changes tracks rapidly.
* **Instructions:**
    1. Locate the "Source Purge" or stream teardown logic triggered when a new seek is requested or the transport is stopped.
    2. Assert that `httpBuffer`, `pcmBuffer1`, and `pcmBuffer2` are explicitly destroyed (e.g., `httpBuffer.destroy()`) alongside the `kill()` commands for the FFmpeg/OBR child processes.
* **TDD Checkpoint:** AGENT INSTRUCTION: While playing the heavy file, rapidly click around the transport timeline (scrubbing) 10-15 times. Ensure the backend does not crash with a memory allocation error and the stream recovers cleanly each time.

## 4. Final Review
status: ✅ Completed
