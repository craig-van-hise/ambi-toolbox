## 📋 PRP: Transport State Machine Hardening (Safe Seek & Loop)

**Target Agent:** React/Electron Full-Stack Developer
**Subsystem:** Global Transport (`Transport.tsx`) & Orchestration Layer

### 1. Objective & Scope
Resolve a race condition occurring during arbitrary-length audio looping. The current implementation allows the React frontend to issue concurrent or premature playback commands while the C++ OBR Sidecar and FFmpeg pipes are in the middle of a teardown/rebuild cycle. The agent must implement a strict "Buffering/Locked" state machine to freeze transport inputs until the new stream is confirmed healthy.

### 2. Architecture Alignment
This task modifies the **Intent → Metadata Probe → Stream Commit** lifecycle. 
* The `playbackIntentRef` must act as the single source of truth.
* When a loop boundary is hit, the frontend must transition to a `LOCKED_REBUILDING` state. 
* The UI must visually indicate a loading/buffering state to the user and ignore all Play/Pause/Seek clicks until the backend IPC emits a `STREAM_READY` event (indicating the first byte of the new WebM chunk has arrived).

### 3. Technical Constraints
* **Non-Blocking:** The state lock must be managed purely in React state (`useState` / `useRef`), never blocking the main thread.
* **Orchestration:** The Electron Main process must handle the hard kill of the existing 3-stage pipe and must gracefully wait for the new `stdout` stream before emitting the ready signal.
* **No Frontend Caching:** Do not attempt to cache the audio buffer in Web Audio API, as loops may be arbitrarily long. 

### 4. Mandatory TDD Phase (The "Green" Gate)
The agent must write and pass a Node.js test script (using Jest or Vitest) that validates the transport state machine. 
* **Test Case:** Simulate a loop trigger event.
* **Assertion:** Verify that calling the `play()` or `seek()` function while the transport is in the `LOCKED_REBUILDING` state results in a no-op (does not mutate `playbackIntentRef`).
* **Exit Condition:** The script must exit cleanly with a code of `0`.

### 5. Licensing Compliance Check
Ensure no new dependencies are introduced that violate the Apache/MIT/LGPL v2.1 boundary. Standard React/Electron state management patterns are strictly required.
