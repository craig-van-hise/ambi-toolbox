# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
**Project:** AmbiToolbox (Electron/React/TypeScript Modular Monolith).
**Current State:** The backend streaming server (`http://localhost:45455/stream`) is delivering audio to the frontend using a WAV/PCM format. Because live streams lack a predefined `Content-Length`, the Chromium media demuxer is arbitrarily resetting at chunk boundaries, causing severe gap-filled playback (approx. 5 dropouts per 25 seconds).
**Objective:** Eliminate browser-side demuxer resets and achieve perfectly gapless playback by switching the final stream delivery format to Ogg/Opus. Opus is natively designed for continuous, headerless HTTP streaming and will seamlessly append frames to the HTML5 `<audio>` element.

## 2. Technical Decisions & Dependencies
* **Root Cause:** Chromium's WAV demuxer is incompatible with open-ended HTTP pipes and resets when hitting chunk boundaries without a known global file size.
* **Architecture Fix:** Update the final `Encoder` stage in the 3-stage pipeline (`Decoder` -> `OBR` -> `Encoder`) to output a high-quality Opus stream wrapped in an Ogg container.
* **FFmpeg Specifications:** We will use `libopus` at 256kbps stereo. The arguments must be: `['-f', 'ogg', '-c:a', 'libopus', '-b:a', '256k', '-vbr', 'on']`.
* **HTTP Header Specifications:** The Node.js server must explicitly declare `Content-Type: audio/ogg` and use `Transfer-Encoding: chunked`. Any hardcoded `Content-Length` headers must be stripped.

## 3. Implementation Phases

### Phase 1: FFmpeg Encoder Reconfiguration (Opus)
* **Objective:** Change the final output of the streaming pipeline from WAV/PCM to a continuous Ogg/Opus stream.
* **Instructions:**
    1. Open the backend streaming logic (likely `electron/handlers/ObrHandler.ts` or `electron/main.ts` where the `obr-stream` endpoint is defined).
    2. Locate the FFmpeg arguments for the final **Encoder** process (the process whose `stdout` is piped to the HTTP `res` object).
    3. Remove any arguments related to WAV, raw PCM, or specific bit depths (e.g., `-f wav`, `-c:a pcm_s24le`).
    4. Inject the following array of arguments for the output format:
       `['-f', 'ogg', '-c:a', 'libopus', '-b:a', '256k', '-vbr', 'on']`
* **TDD Checkpoint:** AGENT INSTRUCTION: Run the TypeScript compiler (`npx tsc --noEmit`) to verify there are no syntax errors in the FFmpeg array modification. Do not proceed to Phase 2 until the compiler outputs a PASS.

### Phase 2: HTTP Header Alignment (Ogg Streaming)
* **Objective:** Instruct the Chromium frontend to engage its continuous Ogg demuxer.
* **Instructions:**
    1. In the same backend streaming file, locate the `res.writeHead(...)` or `res.setHeader(...)` block that responds to the `http://127.0.0.1:45455/obr-stream` GET request.
    2. Update the `Content-Type` header to `'audio/ogg'`.
    3. Ensure the `Transfer-Encoding` header is explicitly set to `'chunked'`.
    4. Add `'Cache-Control': 'no-cache'` and `'Connection': 'keep-alive'` to ensure the browser does not attempt to cache the infinite stream.
    5. **CRITICAL:** Delete any code attempting to calculate or send a `Content-Length` header for this specific endpoint.
* **TDD Checkpoint:** AGENT INSTRUCTION: Launch the application. Load the 25-second 3rd-order Ambisonic test file. Play the file from start to finish. Ensure the Transport UI does not flash "BUFFERING" and there are absolutely zero silent gaps. 

### Phase 3: Scrubbing and Rebuilding Stability Check
* **Objective:** Ensure seeking/scrubbing remains instantaneous with the new Opus encoder.
* **Instructions:**
    1. Opus incurs a very slight encoding latency, but on the M1 hardware, it should be imperceptible. Verify that clicking different points on the Transport timeline successfully tears down the Opus stream, restarts the pipeline, and resumes playback seamlessly without crashing the Node.js process.
* **TDD Checkpoint:** AGENT INSTRUCTION: Rapidly click 5 different locations on the transport scrubber while audio is playing. Do not mark this task as complete until the continuous gapless playback is fully resolved and scrubbing recovers perfectly every time.
