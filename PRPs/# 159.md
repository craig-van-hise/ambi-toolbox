# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
**Context:** AmbiToolbox uses a React frontend to control a Node.js audio streaming pipeline.
**Issue:** The user experiences a fatal transport lockup after stopping playback and attempting to resume. The browser console throws `DOMException: The element has no supported sources.`
**Root Cause:** The previous fix mandated setting `audio.src = ''` to clear the buffer on stop. However, the subsequent `play()` call is either firing against the nulled source before the new cache-busted URL is assigned, or the `HTMLAudioElement` is retaining an invalid internal state.
**Objective:** Replace the "mutate source" pattern with a strict "Destroy and Recreate" lifecycle for the `HTMLAudioElement` within the audio context.

## 2. Technical Decisions & Dependencies
To eliminate state desyncs and `DOMExceptions`, the agent must implement the following architectural mandate:
1.  **Ephemeral Audio Instances:** The `AudioEngineContext` (or wherever the `HTMLAudioElement` is managed) must no longer rely on a persistent `const audio = new Audio()` that lives for the lifetime of the app.
2.  **Destruction on Stop:** When `stop()` is called, the current audio element must be paused, its `.removeAttribute('src')` method called, and its reference strictly set to `null`.
3.  **Instantiation on Play:** When `play()` is called, a completely new instance (`new Audio(cacheBustedUrl)`) must be created, wired up to the necessary event listeners (`ended`, `timeupdate`, etc.), and stored in the ref before calling `.play()`.
