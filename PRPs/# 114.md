# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
**Project:** AmbiToolbox
**Current State:** Playback has a consistent 1-second startup hiccup. Code inspection reveals the backend FFmpeg decoder processes are artificially throttled using the `-re` flag.
**Objective:** Remove the real-time throttling flag (`-re`) from all stream generation pipelines. This will allow the M1 chip to burst-encode the start of the file, instantly filling the browser's media buffer and eliminating the startup starvation hiccup.

## 2. Technical Decisions & Dependencies
* **Root Cause:** The `-re` argument restricts FFmpeg to reading the input file at 1.0x speed. This prevents the backend from building any forward buffer. The browser consumes the audio exactly as fast as it is being produced, leaving zero margin for IPC or startup latency, causing an immediate starvation event.
* **Architecture Fix:** Remove the `'-re'` string from the `spawn` argument arrays in both `ObrHandler.ts` (for the binaural pipeline) and `main.ts` (for the legacy stereo downmix pipeline).
* **Browser Behavior:** The HTML5 `<audio>` element naturally regulates the consumption of the stream. Passing data to it faster than real-time is safe and highly desirable for buffer health.

## 3. Implementation Phases

### Phase 1: Uncap the OBR Pipeline (Binaural)
* **Objective:** Remove the `-re` flag from the 3-stage `createObrPipeline`.
* **Instructions:**
    1. Open `electron/handlers/ObrHandler.ts`.
    2. Locate the `decoder` spawn block around line 35.
    3. Delete the `'-re',` string from the arguments array.
    4. Ensure no trailing commas or broken syntax remain in the array.
* **TDD Checkpoint:** AGENT INSTRUCTION: Run `npx tsc --noEmit` to verify syntax.

### Phase 2: Uncap the Legacy Pipeline (Stereo)
* **Objective:** Remove the `-re` flag from the native FFmpeg stream in `main.ts`.
* **Instructions:**
    1. Open `electron/main.ts`.
    2. Locate the legacy stream route handling inside the `http.createServer` block.
    3. Find the `args` array definition around line 133.
    4. Delete the `'-re', // Real-time reading` string and comment from the array.
* **TDD Checkpoint:** AGENT INSTRUCTION: Launch the application. Load the test file and ensure the Transport UI is set to Binaural (Headphones ON). Press play. The track should now start smoothly without the 1-second hiccup. 

### Phase 3: Final Verification
* **Objective:** Ensure fast-scrubbing stability.
* **Instructions:**
    1. While the track is playing, scrub to various points on the timeline. 
    2. Because FFmpeg is no longer throttled, it will rapidly seek and fill the buffer. Verify that the UI recovers almost instantly and playback resumes without gaps.
* **TDD Checkpoint:** AGENT INSTRUCTION: Toggle the Headphones OFF (Stereo mode) and perform the same scrub tests. Do not mark this task as complete until both pipelines are completely hiccup-free on startup.

## 4. Final Review
Verify that CPU usage briefly spikes when a track starts (as it burst-fills the buffer) and then settles down to a low, stable percentage as Node.js backpressure natively pauses the pipeline when the 10MB buffers are full.
