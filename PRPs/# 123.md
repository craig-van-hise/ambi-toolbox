# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
status: ✅ Completed
The pipeline is failing to decode `.aivu` files because FFmpeg's AudioToolbox wrapper lacks the FourCC mapping for the Apple Positional Audio Codec (`apac`). FFmpeg throws a `no decoder found for: none` error and crashes. 

Because AmbiToolbox targets macOS environments that natively support APAC (macOS 14+), the objective is to re-route `.aivu` files through the `IngestionRouter`. Instead of using Python, the router will spawn macOS's native `/usr/bin/afconvert` utility to decode the `.aivu` spatial audio track into a multi-channel 32-bit Float `.wav` proxy. FFmpeg will then safely stream this proxy file.

## 2. Technical Decisions & Dependencies
status: ✅ Completed
* **Native AVFoundation Decoding:** The agent will use Node's `child_process.spawn` to execute `/usr/bin/afconvert`. This system binary natively ignores MV-HEVC video and flawlessly decodes APAC/ASAF audio tracks using the host OS's Core Audio frameworks.
* **Command Syntax:** The exact command required to generate the proxy is: `afconvert <input_aivu> <output_tmp_wav> -d LEF32@48000 -f WAVE`. This enforces a 32-bit Little-Endian Float PCM output at 48kHz, matching our `f32le` pipeline requirements.

## 3. Implementation Phases
status: ✅ Completed

### Phase 1: Implement Native Apple Ingestion (`IngestionRouter.ts`)
status: ✅ Completed
* **Objective:** Intercept `.aivu` files and transcode them to `.wav` using `afconvert` before FFmpeg touches them.
* **Instructions:**
    1. Open `electron/handlers/IngestionRouter.ts`.
    2. Add `.aivu` back to the interception logic in `prepareStreamTarget`.
    3. Create a distinct branch for `.aivu` files. Do NOT route them to the Python sidecar.
    4. For `.aivu`, define the output temp path (e.g., using `os.tmpdir()` and a path hash, appending `.ambi_tmp.wav`).
    5. Check if the temp file already exists. If it does, return the path immediately (cache hit).
    6. If not, use `spawn` or `execFile` to run `/usr/bin/afconvert` with the following arguments:
       `[originalPath, tempOutputPath, '-d', 'LEF32@48000', '-f', 'WAVE']`
    7. Await the process exit. If the exit code is `0`, return the `tempOutputPath`.

### Phase 2: Pipeline Cleanup (`ObrHandler.ts` & `main.ts`)
status: ✅ Completed
* **Objective:** Ensure the pipeline natively processes the resulting `.wav` proxy without applying video-specific mapping flags to it.
* **Instructions:**
    1. Open `electron/handlers/ObrHandler.ts` and `electron/main.ts`.
    2. The previous fix injected `-map 0:a:0` for video containers. Ensure the logic applies only to standard video containers (`.mp4`, `.mov`, `.mkv`, `.webm`).
    3. Because `.aivu` files are now converted into pure `.wav` proxies *before* reaching FFmpeg, FFmpeg will see the input as a `.wav` file. Therefore, no changes are needed here, but verify that `.wav` inputs do not receive the `-map 0:a:0` flag, as WAV files typically only have a single audio stream (`0:0`).
