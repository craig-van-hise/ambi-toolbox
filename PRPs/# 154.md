## 1. Project Context & Objectives

The `AmbiRotate` tool is currently crashing the backend because the `obr_stream` binary lacks rotation CLI flags. The objective is to implement a hybrid streaming pipeline that utilizes `rotator.py` for spatial rotation before passing the data to `obr_stream` for binauralization. Additionally, UI geometry glitches in the `AmbiRotate` panel must be resolved.

## 2. Technical Decisions & Dependencies

* **Pipeline Insertion:** A 4-stage pipe will be implemented: `Decoder -> Python Rotator -> OBR -> Encoder`.
* 
**Surgical Detox:** Immediately stop passing `--yaw/pitch/roll` to the `obr_stream` binary to prevent Code 1 crashes.


* 
**Clipping Fix:** Constraint slider widths to `calc(100% - 16px)` and normalize container padding to `py-4`.

### Phase 2: Backend Pipeline Refactor (`ObrHandler.ts`) — ✅ Completed

* **Objective:** Insert `rotator.py` into the pipe and fix OBR crashes.
* **What was done:**
  1. `rotator.py` rewritten as a **dual-mode** script:
     - **Mode A** (legacy): File-based `input output --yaw --pitch --roll` for offline export via `AmbiRotate.ts`
     - **Mode B** (new): Streaming `stdin → stdout` f32le PCM for live OBR pipeline via `ObrHandler.ts`
     - Includes identity fast-path (zero rotation = passthrough, zero SH compute overhead)
  2. `ObrHandler.ts` updated:
     - **Removed** `--yaw/--pitch/--roll` from `obr_stream` args (was causing Code 1 crash)
     - **Inserted** `rotator` as Stage 2 between decoder and OBR
     - Pipeline updated: `Decoder → pcmBuffer1 → Rotator → pcmBuffer2 → OBR → pcmBuffer3 → Encoder`
     - `rotator` added to `killAll()` and error handlers
  3. `StreamServer.ts` updated to destructure `[decoder, rotator, obr, encoder]` and kill `rotator` on client disconnect.
  4. `getScriptPath()` helper added to `ObrHandler.ts` (matches `AmbiRotate.ts` resolution logic: `resources/scripts/`)
