# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
status: ✅ Completed
The streaming pipeline is crashing when attempting to play `.ogg` and `.opus` files encoded with high-order Ambisonics (e.g., 3rd Order / 16ch). The native FFmpeg Opus decoder tags the stream with `ambisonic 3`, which causes the `swresample` filter to throw a fatal `Input channel layout 'ambisonic 3' is not supported` error during the `fltp` to `f32le` format conversion.

The objective is to harden the decoding stage in both `ObrHandler.ts` and `main.ts` by bypassing the native Opus decoder, forcing discrete channel layouts, and eliminating implicit `swresample` layout checks.

## 2. Technical Decisions & Dependencies
status: ✅ Completed
* **Input Decoder Forcing:** When an input file ends in `.ogg` or `.opus`, the pipeline MUST prepend `-c:a libopus` before the `-i` flag. The `libopus` decoder handles Ambisonic channels as discrete unassigned channels, which circumvents the `swresample` layout panic.
* **Strict Channel Mapping:** We will eliminate the use of `-ac <channels>` in the pipeline. The `-ac` flag instructs SWR to perform layout mapping. Instead, we will use the `-ch_layout <channels>c` flag (which denotes discrete, unmapped channels) or explicit filter graphs (`channelmap` / `pan`) to route channels one-to-one.
