### Product Requirements Prompt (PRP): Scrubber Debounce & Virtual Playhead (Phased TDD)


> **OBJECTIVE:** Fix the "Scrubber DDOS" (backend hanging from too many seek requests) and the "Playhead Snap to Zero" bugs in the React transport.
> **EXECUTION RULES:** > Use strict TDD across two phases. You must not proceed to Phase 2 until Phase 1's test confirms the backend is no longer being flooded with requests.
> ---
> 
> 
> ### Phase 1: Scrubber Debounce / "Seek End" Isolation (Frontend)
> 
> 
> **CONTEXT:** Dragging the WaveSurfer/Transport scrubber is firing continuous stream regeneration requests, causing a backend deadlock (DDOS).
> **TASK:** Modify `src/contexts/PlaybackContext.tsx` and the Transport component:
> 1. **Decouple Dragging from Fetching:** Do NOT update the `audio.src` URL while the user is actively dragging the scrubber.
> 2. **Implement Debounce/MouseUp:** Only trigger the URL regeneration (`/obr-stream?start=...`) when the user completely releases the mouse (e.g., listening to WaveSurfer's `seek` vs `interaction` events, or using a strict 400ms debounce on the timestamp state change).
> 3. **UI Optimism:** While dragging, visually move the playhead to follow the mouse, but pause the actual HTML5 `Audio` element until the new stream is fetched.
> 
> 
> **TEST:** Write a simple unit test or mock test (`scripts/test-seek-debounce.ts`) that simulates 10 rapid state changes to the seek slider within 200ms, and assert that the function responsible for building the `/obr-stream` URL is called exactly ONCE.
> **CHECKPOINT:** Stop and evaluate. Do not proceed to Phase 2 until the debounce test is green.
> ---
> 
> 
> ### Phase 2: Virtual Playhead Synchronization (Frontend)
> 
> 
> **CONTEXT:** When the new stream starts, FFmpeg resets the container timestamp to 0. The HTML5 Audio element reports `currentTime = 0`, causing the UI to snap back to the beginning instead of the sought position.
> **TASK:** Modify `src/contexts/PlaybackContext.tsx` to use a Virtual Playhead:
> 1. **State Management:** Introduce a `streamOffset` state variable. When a user seeks to 01:15, set `streamOffset = 75` and fetch `/obr-stream?start=75`.
> 2. **Time Translation:** Intercept the `<audio>` element's `timeupdate` event. Instead of passing the raw `audio.currentTime` to the UI, calculate: `virtualTime = streamOffset + audio.currentTime`.
> 3. **WaveSurfer Override:** Ensure WaveSurfer visually renders the playhead at `virtualTime` (relative to the file's total duration) rather than defaulting to the `<audio>` element's `0`. (If using WaveSurfer in MediaElement mode, you may need to update its cursor manually or intercept its internal time state).
> 
> 
> **TEST:** Run the dev server. Manually click to the 30-second mark of a file.
> * **Pass Criteria:** The audio plays from the 30-second mark, AND the WaveSurfer playhead visually remains at the 30-second mark while continuing to advance normally.
> 
> 
> **REPORTING:** Report back only when both the dragging lag and the playhead snap are resolved.
