# Product Requirements Prompt (PRP): OBR Sidecar Integration

**Role:** Senior C++ & TypeScript Integration Engineer
**Objective:** Implement the Open Binaural Renderer (OBR) pipeline into AmbiToolbox.

## 1. Strategic Context & God Rules
status: ✅ Completed

You are tasked with integrating a "Reference Grade" binaural renderer into AmbiToolbox using a native C++ sidecar for high-performance DSP.

**Strict Constraints (DO NOT VIOLATE):**

* **Stability First:** The C++ process must never crash the main application. Use a standalone CLI sidecar pattern.
* **Mandatory TDD:** You must write a Node.js test script to prove the backend pipeline works *before* you update the React UI. Do not ask the user to test broken code in the app.
* **No `npm install` without permission:** Ask first if you need new dependencies.

## 2. Phase 1: Native C++ Implementation (`obr_stream`)
status: ✅ Completed

Create a C++ source file `src/cpp/obr_stream.cc` and a `CMakeLists.txt` to build it.

* **Requirement 1.1 (Stream Logic):** The program must read Raw Float32 PCM from `stdin` and write Stereo Float32 PCM to `stdout`.
* *Constraint:* You MUST explicitly set `stdin` and `stdout` to binary mode (using `_setmode` on Windows) to prevent line-feed corruption.
* *Constraint:* Implement a processing loop that reads `BlockSize * Channels` samples, de-interleaves them into an `obr::AudioBuffer`, calls `obr::ObrImpl::Process()`, interleaves the resulting stereo buffer, and writes to `stdout`. Use a `BlockSize` of 512.


* **Requirement 1.2 (CLI Arguments):**
* `--channels <int>`: Number of input channels.
* `--rate <int>`: Sample rate (strictly 48000).
* `--profile <string>`: "ambient" (default) or "reverberant".


* **Requirement 1.3 (Build System):** Provide a `CMakeLists.txt` that links against the OBR library, compiles with C++17, and configures for macOS Universal Binary (`x86_64;arm64`).

## 3. Phase 2: Electron Backend (`ObrHandler.ts`)
status: ✅ Completed

Create a stream orchestration handler in the backend.

* **Requirement 2.1 (The 3-Stage Pipeline):** Chromium requires a WebM container. You must chain three processes together:
1. **Decode:** Spawn FFmpeg to decode the source file to raw PCM. *(Args: `-i [file] -f f32le -ar 48000 -ac <ch> pipe:1`)*
2. **Process:** Spawn `obr_stream`. Pipe FFmpeg's `stdout` to `obr_stream.stdin`. *(Args: `--channels <ch>`)*
3. **Encode:** Spawn a second FFmpeg process to encode the output to WebM/Opus. Pipe `obr_stream.stdout` to this encoder's `stdin`. *(Args: `-f f32le -ar 48000 -ac 2 -i pipe:0 -c:a libopus -b:a 192k -f webm pipe:1`)*


* Return the final encoder's `stdout` stream to the HTTP response, ensuring `Content-Type: audio/webm` is set.


* **Requirement 2.2 (Error Handling):** Listen for error events on all three processes. If any process dies, `SIGKILL` the others to prevent zombie memory leaks.
