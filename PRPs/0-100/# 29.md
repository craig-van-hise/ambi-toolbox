Overhaul the `AmbiRotate` UI and Playback Engine to fix interaction issues, transport logic, and loading feedback.

**1. Fix Slider "Drag" Behavior**

* **Root Cause:** If the sliders only jump on click but don't drag smoothy, it is usually because the `onChange` event is triggering a heavy re-render of the entire component, or the state update is lagging behind the mouse.
* **Fix:**
* Ensure the `<input type="range">` is using `value={localState}` and updating via `onChange`.
* **Optimization:** Do **not** re-initialize the Audio Engine on every slider move. The `useEffect` hook must strictly call `nativeRotator.setRotation(...)` without tearing down the graph.



**2. Fix Transport Logic (Standardizing)**

* **Play/Pause Button:**
* *Current:* Toggles Play/Stop.
* *New:* Toggles **Play/Pause**.
* *Icon:* Shows `▶` when paused, `||` when playing.


* **Stop Button:**
* *Action:* Stops playback **AND** resets the Playhead (Scrubber) to 0 or the Loop Start point.


* **Loop Functionality:**
* Add **"Set In"** (`[`) and **"Set Out"** (`]`) buttons next to the loop toggle.
* *Logic:* When clicked, they capture the current playhead position as the loop boundary.
* *Visual:* Draw a colored highlight segment on the scrubber track between the In/Out points.
* *Engine:* Update `sourceNode.loopStart` and `sourceNode.loopEnd` instantly.



**3. Implement "Immediate" Feedback (The Progress Bar)**

* **The Problem:** 10s of silence with no feedback is unacceptable.
* **The Fix:**
* **Loading Bar:** Create a visible Progress Bar overlay that appears immediately on file drop.
* *Data Source:* The backend already emits "Reading chunk X%". We must listen to this IPC event in React and update the bar.
* *Instant Start (Streaming Attempt):* While true streaming of WAVs is hard, we can **Decode the first chunk (50MB)** immediately and start playing it while the rest loads in the background.
* *Phase 1 Implementation:* Just get the **Progress Bar** working first. It solves the "Is it broken?" user anxiety.
