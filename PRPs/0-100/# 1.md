
**Role:** Senior Full-Stack Architect (Electron/React/TypeScript)

**Objective:**
Re-architect the "AmbiToolbox" project from a collection of loose Python scripts into a single, monolithic **Electron Desktop Application**. You will merge the existing backend logic with a new frontend prototype.

**1. Context & The Pivot**

* **Previous State:** We were building independent Python/PyQt tools.
* **New State:** We are building **ONE** unified Electron app ("AmbiToolbox") with a sidebar navigation to access the different tools.
* **Tech Stack:** Electron (Backend), React + TypeScript + Tailwind CSS (Frontend).

**2. Input Sources**

* **Frontend Source:** `root/Front End Design From AI Studio/`
* Contains the React components, Tailwind config, and UI layout generated by an AI designer. **Use this exactly as the foundation.**


* **Backend Logic Source:** `root/Apps/`
* Contains the working Python versions of **Ambix2Opus**, **Ambix2IAMF**, and **Ambix2Bin**.
* *Note:* You must read the Python code to understand the FFmpeg/Binary arguments used, but you will **port this logic to TypeScript** (Node.js `child_process`) rather than bundling the Python scripts.



**3. Architectural Requirement: "Modular Monolith"**
We need a strict separation of concerns. Do not dump all logic into one file.

* **Frontend:** `src/tools/[ToolName]/` (e.g., `src/tools/Ambix2Opus/index.tsx`)
* **Backend:** `electron/handlers/[ToolName].ts` (Logic for constructing commands and handling file I/O for that specific tool).
* **Bridge:** Use a standardized `preload.ts` to expose a generic `runConversion` or `runTask` API that accepts a tool ID (e.g., `'ambix2opus'`) and options.
