### Product Requirements Prompt (PRP): The "Stop/Play" Mimicry Strategy

> **CRITICAL REFACTOR: BROWSER AUTOPLAY POLICY VIOLATION**
> The previous implementation using `setTimeout` and `removeAttribute` detached the `.play()` call from the user's double-click gesture. This caused the browser's autoplay policy to silently block playback, leaving the track stuck at 0:00. However, the Transport's physical Stop and Play buttons work perfectly.
> **EXECUTION RULES:**
> Use strict TDD. Revert the asynchronous hacks and route the queue's double-click directly through the proven Transport methods.
> ---
> 
> 
> ### Phase 1: Revert Asynchronous Hacks (Frontend)
> 
> 
> **TASK:** In `src/contexts/PlaybackContext.tsx` or wherever the track switching logic lives:
> 1. **REMOVE** the `setTimeout` completely.
> 2. **REMOVE** the `audio.removeAttribute('src')` or `audio.src = ''` hacks.
> **TEST:** Run the compiler to ensure no syntax errors exist after the cleanup.
> 
> 
> ---
> 
> 
> ### Phase 2: Wire Queue to Transport Methods (Frontend)
> 
> 
> **CONTEXT:** The Transport components have working `stop()` and `play()` functions. The queue must literally mimic a user pressing these buttons.
> **TASK:** When a user double-clicks a file in the queue:
> 1. Synchronously call the exact same `stop()` or `reset()` function that the Transport's Stop button uses.
> 2. Update the `currentFile` state.
> 3. Synchronously apply the new `/obr-stream` URL to the HTML5 Audio element.
> 4. Synchronously call `audio.play().catch(e => console.error("Play blocked:", e))` within the exact same execution block as the double-click event handler. Do not wait for a `useEffect` to trigger the play command.
> 
> 
> **TEST:** Write a React component test (`scripts/test-queue-click.ts`) that simulates a double-click on the queue list item and asserts that `audio.pause()` and `audio.play()` are called synchronously in the same tick.
> **CHECKPOINT:** Stop and evaluate. Do not proceed until the test confirms synchronous execution.

> ### Phase 3: Initial Load Autoplay Guard (Frontend)
> 
> 
> **CONTEXT:** When files are first dragged into the app, the first file is selected and tries to play, but gets stuck because dragging files is not a valid play gesture.
> **TASK:** > 1. When populating the queue from a drag-and-drop or file dialog, select the first file, load the URL into the audio element, but **DO NOT call `.play()**`.
> 2. Leave it in a "Paused/Ready" state so the user must explicitly hit the Transport Play button or double-click to start the initial session.
> **REPORTING:** Output the exact error message from the `.catch()` block if the audio still fails to play upon double-clicking.
