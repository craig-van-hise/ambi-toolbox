

# Product Requirements Prompt: Fix Content Security Policy (CSP)

**Criticality:** BLOCKER
**Diagnosis:** The application's security policy prohibits fetching data from `blob:` URLs, which `wavesurfer.js` (WebAudio backend) requires to render the waveform.
**Fix:** Update the `Content-Security-Policy` meta tag to explicitly allow `blob:` and `data:` schemes in the `connect-src` directive.

## 1. Edit the HTML Entry Point

**File:** `index.html` (This is usually in your project root or `public/` folder).
**Action:** Locate the `<meta http-equiv="Content-Security-Policy" ...>` tag.

**Replace the existing CSP with this Permissive Configuration:**

```html
<meta http-equiv="Content-Security-Policy" content="
  default-src 'self';
  script-src 'self' 'unsafe-inline' 'unsafe-eval';
  style-src 'self' 'unsafe-inline';
  img-src 'self' blob: data: media:;
  font-src 'self' data:;
  media-src 'self' blob: data: media:;
  connect-src 'self' blob: data: media: ws: http: https:;
">

```

**Key Changes:**

* **`connect-src`**: Added `blob:` (This fixes your specific error).
* **`media-src`**: Added `blob:` (Ensures audio playback isn't blocked later).
* **`img-src`**: Added `blob:` (Ensures the waveform canvas can be drawn if it uses blob images).

## 2. Verify Electron Main Process (If applicable)

**File:** `electron/main.ts`
**Check:** If you are setting CSP headers programmatically in `session.defaultSession.webRequest.onHeadersReceived`, ensure the logic there matches the HTML meta tag above. If you are *not* doing this, ignore this step and rely on the HTML tag.
