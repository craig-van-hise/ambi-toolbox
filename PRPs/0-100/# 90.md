
### Product Requirements Prompt (PRP): High-Performance Transport Switching

> **OBJECTIVE:** Resolve playback latency and "start-from-middle" bugs when switching tracks. Ensure immediate, sample-accurate starts for new stream requests.
> **CONTEXT:** > When switching tracks in the UI, there is a multi-second delay, and the audio starts seconds into the file. This is caused by "Buffer Pollution": the new FFmpeg process is writing data into pipes that still contain data or active handles from the previous process.
> **EXECUTION RULES:**
> Use strict TDD across two phases. You must not proceed to Phase 2 until the transition test in Phase 1 passes.
> ---
> 
> 
> ### Phase 1: Aggressive Pipeline Reset (Backend)
> 
> 
> **TASK:** Modify `ObrHandler.ts` to ensure the pipeline is "Cold" before starting a new one.
> 1. **Immediate Termination:** On every new request to `/obr-stream`, explicitly call a cleanup function that sends `SIGKILL` to any existing `ffmpeg` or `obr_stream` processes associated with that session *before* spawning new ones.
> 2. **Pipe Flushing:** Ensure that the Node.js `res` object and all internal PassThrough streams are fully drained and unpiped.
> 3. **FFmpeg Fast-Start:** Add the `-probesize 32` and `-analyzeduration 0` flags to the **Decoder FFmpeg** instance to stop it from "waiting" to analyze the file before it starts spitting out PCM.
> 
> 
> **TEST:** Write `scripts/test-track-switching.ts`.
> * Start a stream for File A.
> * Wait 500ms, then immediately request File B on the same connection.
> * Measure the time between the request for File B and the first byte received.
> * **Pass Criteria:** Time-to-first-byte must be < 200ms, and the backend logs must show "Killing previous processes" before "Spawning new pipeline."
> 
> 
> ---
> 
> 
> ### Phase 2: Frontend Sync & State Guard (Frontend)
> 
> 
> **TASK:** Modify `src/contexts/PlaybackContext.tsx` to handle the HTML5 Audio lifecycle properly.
> 1. **The "Stop-Before-Swap" Pattern:** When the file changes, explicitly call `audio.pause()`, set `audio.src = ""`, and call `audio.load()` to purge the browser's internal buffer *before* setting the new `/obr-stream` URL.
> 2. **Async Play Guard:** Wrap the `.play()` call in a check that ensures the `src` is actually set and use the promise-based return of `.play()` to catch and ignore the "interrupted by pause" DOMException.
> 3. **Reset Metadata:** Ensure all progress/time states are zeroed out the instant a new probe begins, so the UI doesn't show the old seek position.
> 
> 
> **TEST:** Run the app and verify the `PlaybackContext` logs.
> * **Pass Criteria:** No "Resume failed" DOMExceptions in the console, and the "Switching stream" log must be preceded by an "Audio Reset" log.
> 
> 
> **REPORTING:** Report back only when the switching latency is eliminated and `test-track-switching.ts` is green.
