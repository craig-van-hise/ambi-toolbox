**Task:**
Implement the Full Stack (Frontend UI + Backend Logic) for the **Ambix2CAF** tool.

**1. Context & Constraints**

* **Goal:** Convert multi-channel Ambisonics (specifically 3rd Order/16ch) into Apple's `.caf` format.
* **Engine:** Use the bundled **FFmpeg** binary. (Do **NOT** use `afconvert`, as this app must remain cross-platform compatible).
* **Input:** 16-channel `.wav` (3rd Order Ambisonics).
* **Output:** `.caf` (Core Audio Format).

**2. Frontend Requirements (`src/tools/Ambix2CAF/index.tsx`)**
Update the UI to replace the generic placeholder with these specific controls:

* **Section 1: Layout Tag (The "Label")**
* **Label:** "Spatial Layout Tag"
* **Control:** `Select` / Dropdown
* **Option A (Default):** "Discrete (Recommended)"
* *Tooltip/Note:* "Safest. Labels as 16 channels, no specific order."


* **Option B:** "HOA ACN SN3D (Modern)"
* *Tooltip/Note:* "For recent Apple workflows only."




* **Section 2: Bit Depth**
* **Label:** "Bit Depth"
* **Control:** `Select` / Dropdown
* **Option A (Default):** "24-bit Integer (Standard)"
* **Option B:** "32-bit Float (Processing)"
* **Option C:** "16-bit Integer (Space Saving)"


* **Action Button:** "Convert to CAF" (Silver/Gray).

**3. Backend Requirements (`electron/handlers/ambix2caf.ts`)**
Create the handler to map the UI selections to FFmpeg arguments.

* **Codec Mapping (Bit Depth):**
* **24-bit Integer**  `-c:a pcm_s24le` (Note: CAF is versatile, but `s24le` is standard safe).
* **32-bit Float**  `-c:a pcm_f32le`
* **16-bit Integer**  `-c:a pcm_s16le`


* **Layout Mapping (The Tricky Part):**
* **Discrete:** Ensure FFmpeg does *not* try to force a standard surround layout. We want a direct 1:1 channel map. You may need to use `-channel_layout unknown` or simply map input streams directly if FFmpeg defaults to something weird.
* **HOA ACN SN3D:** FFmpeg likely cannot write the proprietary Apple 'HOA' atom. For now, treat this identical to "Discrete" in the backend but **log a warning** that metadata tagging might be limited in FFmpeg. The audio data itself must remain untouched (ACN ordering is standard).
