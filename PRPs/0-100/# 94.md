### Product Requirements Prompt (PRP): Scrubber Auto-Resume Logic

> **OBJECTIVE:** Fix the "pause on seek" bug. The audio transport must remember its play state across stream URL changes. If the track was playing before the seek, it must automatically resume playing from the new position. If it was paused, it should remain paused.
> **EXECUTION RULES:** > Use strict TDD across two phases. Do not proceed to Phase 2 until Phase 1 passes.
> ---
> 
> 
> ### Phase 1: State Memory & Auto-Play (Frontend)
> 
> 
> **CONTEXT:** Changing the HTML5 `Audio.src` to fetch the new `/obr-stream?start=...` URL inherently pauses the audio. We must programmatically resume it if the user was actively listening.
> **TASK:** Modify the seek handling logic in `src/contexts/PlaybackContext.tsx`:
> 1. **Capture State:** At the exact moment a seek is initiated (after the debounce, right before changing the URL), capture the current playback state: `const wasPlaying = !audio.paused;` (or check your internal `isPlaying` React state).
> 2. **Apply URL:** Update `audio.src` and call `audio.load()`.
> 3. **Conditional Resume:** Wait for the `audio` element to fire the `canplay` or `loadedmetadata` event for the new stream. If `wasPlaying` was true, immediately call `audio.play().catch(...)`.
> *(Note: Do not blindly call `.play()` immediately after setting `.src` without waiting for the buffer, or the browser may throw a DOMException).*
> 
> 
> **TEST:** Write a programmatic test (`scripts/test-auto-resume.ts` or similar unit test) that mocks the `<audio>` element.
> * Simulate `audio.paused = false`.
> * Trigger the seek function.
> * Assert that the seek function correctly captures the state, updates the URL, and ultimately calls `.play()` on the mock audio object.
> **CHECKPOINT:** Stop and evaluate. Do not proceed until this logic is verified.
