### Product Requirements Prompt (PRP): Low-Latency Seek Support


> **OBJECTIVE:** Implement low-latency server-side seeking. Moving the playhead in the UI must result in near-instantaneous audio resumption from the new timestamp.
> **CONTEXT:** > The current `/obr-stream` endpoint does not handle time offsets. When a user seeks, the browser is forced to wait for a full pipeline teardown and restart. We must pass the seek timestamp directly to the FFmpeg decoder.
> **EXECUTION RULES:** > Use strict TDD. Phase 1 must verify that the backend can start a stream from an arbitrary offset before modifying the frontend.
> ---
> 
> 
> ### Phase 1: Seek Parameter Injection (Backend)
> 
> 
> **TASK:** Modify `ObrHandler.ts`:
> 1. **Add `start` Query Parameter:** Update the endpoint to accept an optional `start` parameter (e.g., `/obr-stream?file=...&start=45.5`).
> 2. **Decoder Seek:** In the **Decoder FFmpeg** command, inject the `-ss` flag using the `start` value.
> * **Crucial:** The `-ss <seconds>` flag MUST come *before* the `-i <file>` flag for "Fast Seeking" (input seeking).
> 
> 
> 3. **Kill-on-Seek:** Ensure that if a new request comes in for the same file but a different `start` time, the previous pipeline is killed instantly to free the port/socket.
> 
> 
> **TEST:** Write `scripts/test-seek-accuracy.ts`.
> * Request a file with `start=10`.
> * Capture the first 2 seconds of output.
> * Manually verify (or use a probe) that the audio data matches the 10-second mark of the source file, not the beginning.
> **CHECKPOINT:** Do not proceed until you can prove the backend starts from the correct offset.
> 
> 
> ---
> 
> 
> ### Phase 2: React Scrubber Integration (Frontend)
> 
> 
> **TASK:** Modify `src/contexts/PlaybackContext.tsx`:
> 1. **Listen for Seek Events:** Intercept the WaveSurfer/Transport seek event.
> 2. **URL Re-generation:** When a seek occurs, do NOT just let the browser handle it. Construct a new URL for the `audio.src` that includes the `&start=${newTimestamp}` parameter.
> 3. **Burst Start:** Before calling `audio.play()`, set `audio.currentTime = newTimestamp` so the UI playhead stays in sync with the new stream's data.
> 4. **Add Cache-Busting:** Append a unique timestamp `&_t=${Date.now()}` to the URL on every seek to prevent the browser from trying to use a stale, partially-downloaded buffer.
> 
> 
> **TEST:** Manually verify by clicking different points on the waveform.
> * **Pass Criteria:** Audio should resume within < 500ms of the click.
> 
> 
> **REPORTING:** Report back once the "Scrubber Lag" is reduced to an acceptable commercial level.
