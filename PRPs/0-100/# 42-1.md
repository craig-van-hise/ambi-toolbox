### PRP 42-1: Backend Bridge Expansion

**Objective:** Securely expose file selection and path expansion APIs without breaking legacy tool functionality.

> **Instruction for Agent:**
> We are upgrading the Electron backend bridge. You must modify `electron/preload.ts` and `electron/main.ts`.
> **1. `electron/preload.ts` Modification:**
> * **CRITICAL CONSTRAINT:** You must **NOT** delete or overwrite the existing `contextBridge.exposeInMainWorld('electron', ...)` implementation. The legacy tools (Ambix2Opus, etc.) depend on this specific bridge.
> * **Action:** *Append* a new bridge exposure named `electronAPI` alongside the existing `electron` bridge.
> * **API Definition:** The `electronAPI` object must expose:
> * `selectFiles`: A function that triggers the native file dialog.
> * `expandPaths`: A function that accepts a path and returns a full file list (for directory drops).
> 
> 
> 
> 
> **2. `electron/main.ts` Modification:**
> * Add the corresponding IPC handlers for the new API methods:
> * Handle `dialog:openFile` (mapped to `selectFiles`).
> * Handle `app:expandPaths`.
> 
> 
> 
> 
> **Context:** This ensures our new `SmartDropZone` (coming next) can handle native file dialogs while keeping the old Drag-and-Drop logic functional for older tools.
