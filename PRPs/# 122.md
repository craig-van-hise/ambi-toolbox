# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
The playback of `.aivu` (Apple Immersive Video Universal) files is currently failing. Log analysis reveals that the `IngestionRouter` is incorrectly intercepting `.aivu` files and passing them to a Python sidecar. The Python script cannot decode Apple's proprietary APAC format, so it mangles the file into a generic 4-channel proxy WAV. When the OBR pipeline attempts to apply a high-order ambisonic channel map to this flattened proxy, the pipeline crashes.

The objective is to stop routing `.aivu` to Python. Instead, we will pass it directly to our custom FFmpeg build (which has native `--enable-audiotoolbox` support), explicitly isolating the audio track using `-map 0:a:0` to avoid processing the 8K video stream.

## 2. Technical Decisions & Dependencies
* **Bypass IngestionRouter:** `.aivu` files MUST be removed from the `IngestionRouter`'s proprietary list. They must pass straight to the native FFmpeg `Decoder`.
* **Explicit Audio Mapping:** For all video containers (`.aivu`, `.mp4`, `.mov`, `.mkv`, `.webm`), we must inject `-map 0:a:0` into the FFmpeg arguments *after* the `-i` flag to extract only the audio track and discard the video track.

## 3. Implementation Phases

### Phase 1: Remove `.aivu` from Python Routing
* **Objective:** Stop the Python sidecar from mangling Apple spatial audio files.
* **Instructions:**
    1. Open `electron/handlers/IngestionRouter.ts`.
    2. Locate the logic that checks for proprietary formats (e.g., checking if the extension is `.iamf`, `.mat`, or `.aivu`).
    3. **Remove `.aivu`** from this condition entirely. 
    4. Ensure that when an `.aivu` file is processed by `prepareStreamTarget`, it bypasses the Python transcode step and returns the `originalPath` unchanged.
* **TDD Checkpoint:**
    AGENT INSTRUCTION: Write or update a unit test for `IngestionRouter`. Assert that passing an `.aivu` file path to `prepareStreamTarget` directly returns the exact same `.aivu` file path without triggering a Python spawn. Do not proceed to Phase 2 until this validates.

### Phase 2: Native Audio Extraction (`ObrHandler.ts`)
* **Objective:** Ensure FFmpeg natively decodes the container while completely ignoring the MV-HEVC video track.
* **Instructions:**
    1. Open `electron/handlers/ObrHandler.ts`.
    2. In `createObrPipeline`, determine if the file is a video container using this logic:
       `const isVideoContainer = ['.aivu', '.mp4', '.mov', '.mkv', '.webm'].some(ext => inputPath.toLowerCase().endsWith(ext));`
    3. Find where the input file is added to `decoderArgs` (e.g., `'-i', inputPath`).
    4. If `isVideoContainer` is true, inject the arguments `'-map', '0:a:0'` into `decoderArgs` immediately *after* the input path string.
    5. Retain the `channelmap` filter logic from previous fixes to ensure the decoded APAC layout maps 1-to-1 cleanly to `f32le`.
    
### Phase 3: Native Audio Extraction (`main.ts`)
* **Objective:** Ensure the legacy `/stream` endpoint also securely isolates audio for containers.
* **Instructions:**
    1. Open `electron/main.ts` and locate the legacy `/stream` HTTP logic.
    2. Implement the same `isVideoContainer` detection logic based on `filePath`.
    3. Locate the `args` array for the FFmpeg spawn. Inject `'-map', '0:a:0'` immediately *after* `'-i', filePath`.

## 4. Final Review
Start the application and drop the `Desert_Extreme.aivu` file into the UI. Verify in the terminal logs that `[IngestionRouter] Proprietary format detected` does **not** trigger. Verify that FFmpeg spawns, correctly applies `-map 0:a:0`, and begins playback natively. Note: If a user drops a standard 5.1/Stereo `.mp4` into the Ambisonic pipeline, OBR will reject the channel count (e.g., `Invalid channel count 6`). This is intended behavior, as OBR strictly requires Ambisonic channel counts (4, 9, 16, 25).
