

# Product Requirements Prompt: UI Implementation for "AmbiTrim"

**Role:** Frontend Specialist & UI Designer
**Objective:** Implement the visual interface for the new "AmbiTrim" tool.
**Constraint:** You must strictly adhere to the existing design system found in `Ambix2Opus`. Do not invent new layouts.
**Reference:** Use the analysis below derived from the application screenshot.

## 1. Design System Analysis (Strict Compliance)

Before writing code, acknowledge the following design rules:

* **Global Layout:**
* **Sidebar (Left, Fixed):** Navigation tabs. Active tab has a colored border (Gold/Orange) and lighter background.
* **Main Canvas (Right, Flexible):** Divided vertically into **Header**, **Workspace (Top)**, and **Control Deck (Bottom)**.


* **Color Palette:**
* **Backgrounds:** Deep Navy/Black (`bg-slate-900` or similar).
* **Accents:** Neon Purple (`text-purple-400`) for headers, Solid Purple Gradient for primary buttons.
* **Text:** White for primary, Grey for sub-headers.


* **Component Structure:**
* **The "Workspace" (Top Right):** Always contains the Drop Zone. In AmbiTrim, this zone must transform into the Waveform Viewer upon file load.
* **The "Control Deck" (Bottom Right):** Separated by a horizontal divider (`border-t`). Contains inputs and the primary action button.
* **Primary Button:** Full width, rounded corners, purple background, located at the very bottom of the Control Deck.

### Step 3: Component State Logic

* **State A (Idle):**
* **Workspace:** Shows large dashed-border Drop Zone (Match the reference image exactly: centered icon, "Drag Audio Files..." text).
* **Control Deck:** Inputs are disabled or hidden. Button is disabled.


* **State B (File Loaded):**
* **Workspace:** The Drop Zone disappears. The `wavesurfer` canvas takes its place, filling the available width.
* **Control Deck:** Inputs are active. Button is active (Purple).
