# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
**Project:** AmbiToolbox
**Current State:** Loading 7th-order Ambisonics (64 channels) causes a dual-crash: the frontend Web Audio API fails (max 32 channels) and the backend OBR pipeline fails (max 4th order / 25 channels).
**Objective:** Implement strict truncation to the maximum supported orders. The backend OBR pipeline will truncate any stream >25 channels down to 25 channels (4th Order). The frontend `WavDecoder` will cap buffer allocations to 32 channels to prevent fatal DOMExceptions.

## 2. Technical Decisions & Dependencies
* **Backend Truncation (FFmpeg):** We will intercept the channel count in `createObrPipeline`. If `channels > 25`, we will cap the OBR input to 25 and inject an FFmpeg `pan` filter into the decoder stage.
* **The Truncation Filter:** `pan=25c|c0=c0|c1=c1|...|c24=c24`. This preserves the first 25 ACN channels (0 through 24) and discards higher-order data.
* **Frontend Safety:** Modify `WavDecoder.ts` to cap `AudioContext.createBuffer` using `Math.min(channels, 32)`.

## 3. Implementation Phases

### Phase 1: Backend 4th-Order Truncation
* **Objective:** Ensure the OBR binary never receives more than 25 channels of PCM data.
