### Product Requirements Prompt (PRP): Previous/Next Transport Wiring


> **OBJECTIVE:** Wire up the "Previous" and "Next" buttons on the Transport UI to cycle through the file queue. They must utilize the exact same 3-Step Linear Pipeline and `playIntentRef` logic as double-clicking a file.
> **EXECUTION RULES:**
> Use strict TDD. Do NOT alter the audio streaming logic or the `useEffect` hooks in `PlaybackContext`. You are only adding queue-navigation functions and wiring UI onClick events.
> ---
> 
> 
> ### Phase 1: Queue Navigation Logic (Frontend Context)
> 
> 
> **CONTEXT:** The `PlaybackContext` (or your state store) needs helper functions to determine what the "next" or "previous" file is based on the current queue/playlist.
> **TASK:** In `src/contexts/PlaybackContext.tsx` (or where your queue state lives):
> 1. Create two new functions: `playNextTrack()` and `playPreviousTrack()`.
> 2. Inside these functions, find the index of the `currentFile` within the `fileQueue` array.
> 3. Calculate the target index (e.g., `currentIndex + 1`). If the target index is out of bounds (end of the list), either safely return/do nothing, or loop back to index 0 (depending on existing app preferences).
> 4. Once the target file is identified, execute the **exact same Step 1 Intent** logic used by the queue double-click:
> * `audio.pause()`
> * `playIntentRef.current = true;` (to ensure it auto-plays)
> * `setCurrentFile(targetFile);`
> 
> 
> 
> 
> **TEST:** Write a unit test (`scripts/test-queue-navigation.ts`) that mocks a `fileQueue` array of 3 files. Set file 1 as active. Call `playNextTrack()` and assert that file 2 becomes active and `playIntentRef.current` is true. Call `playPreviousTrack()` and assert file 1 becomes active again.
> **CHECKPOINT:** Stop and evaluate. Do not proceed until the navigation logic is verified.
> ---
> 
> 
> ### Phase 2: Transport UI Wiring (Frontend Components)
> 
> 
> **CONTEXT:** The physical buttons in the UI need to trigger these new context functions.
> **TASK:** In `src/components/Transport.tsx`:
> 1. Consume `playNextTrack` and `playPreviousTrack` from the context.
> 2. Attach them to the `onClick` props of the respective Previous and Next buttons.
> 3. **UI Polish (Optional but recommended):** Disable the "Previous" button if `currentIndex === 0`. Disable the "Next" button if `currentIndex === fileQueue.length - 1`.
> 
> 
> **REPORTING:** Report back once clicking Previous and Next successfully transitions between tracks and auto-plays the new selection.
