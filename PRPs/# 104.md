## 📋 PRP: Transport Loop Resiliency & Timeline State Machine

**Target Agent:** React/Electron Full-Stack Developer
**Subsystem:** Global Transport (`Transport.tsx`) & Orchestration Layer

### 1. Objective & Scope
Resolve a stream deadlocking issue where arbitrary-length looping freezes the transport after the first iteration. The React frontend is currently desynchronizing with the heavy C++ OBR / FFmpeg pipeline during the loop's teardown/rebuild phase. The agent must implement a resilient `LOCKED_REBUILDING` state for loop triggers and explicitly decouple visual timeline scrubbing from backend IPC seek commands to prevent process exhaustion.

### 2. Architecture Alignment
This task refines the **Intent → Metadata Probe → Stream Commit** lifecycle by introducing a precise lock during heavy backend rebuilds.

* **Loop Boundary Trigger:** When the playback head hits the Right Locator, the frontend must issue a single `seek` command to the Left Locator and immediately enter a `LOCKED_REBUILDING` state. 
* **Scrubbing Protection:** Dragging the transport handle must update *only* the local React visual state (`onChange`). It must absolutely **NOT** trigger an IPC seek. The backend `seek` command must only fire on `onMouseUp`, `onTouchEnd`, or `onChangeCommitted`.

* **The Handshake & Timeout:** While locked, the UI must show a buffering indicator and ignore further playback inputs. The lock is only released when the Electron main process emits a `STREAM_READY` IPC event. If this event is not received within a 3000ms timeout, the UI must automatically unlock and log a stream timeout warning.

### 3. Technical Constraints
* **Non-Blocking:** All state locking, debouncing, and timeout timers must be handled purely in the React renderer process using native hooks.
* **Orchestration:** The Electron Main process must handle the hard kill of the existing 3-stage pipe and gracefully wait for the new `stdout` stream from the OBR sidecar before emitting `STREAM_READY`.
* **State Integrity:** Ensure the `playbackIntentRef` does not mutate while in the locked state, preventing race conditions from impatient user clicks.

### 4. Mandatory TDD Phase (The "Green" Gate)
The agent must write/update Node.js test scripts (Jest/Vitest) validating the updated state machine:
* **Test Case 1 (Loop Trigger):** Simulate hitting the loop boundary. Assert that the IPC `seek` command fires exactly `1` time and the state transitions to locked.
* **Test Case 2 (Scrubbing Isolation):** Simulate 50 rapid `onChange` events on the timeline slider. Assert that the IPC `seek` command is called exactly `0` times.
* **Test Case 3 (Commit & Unlock):** Simulate an `onMouseUp` event, followed by a mocked `STREAM_READY` IPC event. Assert the UI returns to an active, playing state.
* **Test Case 4 (Timeout Recovery):** Trigger a seek, withhold the `STREAM_READY` event, and assert the UI unlocks automatically after the timeout threshold.
